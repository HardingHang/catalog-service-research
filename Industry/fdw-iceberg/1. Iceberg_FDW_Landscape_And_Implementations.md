## 0. 核心辨析：Iceberg SDK vs Iceberg FDW

### 0.1 概念定义

**Iceberg SDK（格式库）**：实现 Iceberg 表格式规范的独立库，职责是读懂三层元数据结构，规划数据文件列表，读取数据文件。**不涉及 PostgreSQL**，可被任何引擎调用。

| SDK 职责 | 描述 |
|----------|------|
| 元数据遍历 | `metadata.json` → `manifest-list.avro` → `manifest-N.avro` |
| 文件规划 | 输出 `FileScanTask` 列表（每个任务对应一个数据文件） |
| 谓词下推评估 | 谓词 × 分区摘要/列统计 → 剪枝（manifest list 层 + manifest 层） |
| 数据文件读取 | 通过 Parquet reader（通常基于 Arrow）读取 `.parquet` 文件 |
| Schema evolution | 基于 field_id（而非列名）做投影映射 |
| Catalog 客户端 | 从 REST/HMS/Glue 等服务解析 `metadata.json` 路径 |

**Iceberg FDW（PostgreSQL 扩展）**：实现 `FdwRoutine` 回调接口的数据库扩展，将 Iceberg 表暴露为 PG 外部表。**不直接解析 Iceberg 格式**，由 SDK 完成。

| FDW 职责 | 描述 |
|----------|------|
| Planner 集成 | 实现 `GetForeignRelSize / GetForeignPaths / GetForeignPlan` |
| Executor 集成 | 实现 `BeginForeignScan / IterateForeignScan / EndForeignScan` |
| 类型转换 | Arrow 类型 → `Datum`，填入 `TupleTableSlot` |
| 内存管理 | PG `MemoryContext` 体系下管理批次内存 |
| fdw_private 编码 | 规划→执行阶段传递文件列表、投影列、残差谓词 |
| Catalog 查询 | 从系统表或外部 Catalog 获取 `metadata.json` 路径 |

### 0.2 协作关系

```
PostgreSQL / GaussDB 进程
  │
  ├─ FDW 层（.c/.cpp 扩展，实现 FdwRoutine）
  │    · GetForeignPaths/Plan：调用 SDK「文件规划」，获取 FileScanTask 列表
  │    · BeginForeignScan/IterateForeignScan：调用 SDK「数据读取」，获取 Arrow batch
  │    · 将 Arrow batch → TupleTableSlot → 返回给 PG Executor
  │
  └─ SDK 层（独立库，FDW 的依赖）
       · Iceberg 格式解析（metadata.json / Avro manifest）
       · FileScanTask 规划 + 谓词剪枝
       · Parquet 数据文件读取（Arrow C++ / Arrow C Data Interface）
       ↓
  对象存储（S3 / OBS）
```

**关键推论**：`iceberg-cpp / iceberg-cxx / duckdb-iceberg / iceberg-rust` 都是 **SDK**；`pg_lake / supabase/wrappers` 是 **FDW**，它们分别以 duckdb-iceberg 和 iceberg-rust 为 SDK 层。`parquet_fdw` 是 FDW 但无 Iceberg SDK 层，是 FDW 层代码的最直接参考。

## 2. Iceberg FDW 实现分析

### 2.1 Snowflake/pg_lake（C FDW + DuckDB SDK）

**GitHub**: https://github.com/Snowflake-Labs/pg_lake · 开源 2025-11  
**架构**: PostgreSQL C 扩展（FDW 层） + pgduck_server 独立进程（SDK 层 = DuckDB + duckdb-iceberg）

#### 双进程架构

```
PostgreSQL 进程（C FDW 扩展）
  GetForeignPaths/Plan
    → data_file_pruning.c    ← 分区/文件裁剪（C 实现，不依赖 DuckDB）
    → deparse.c              ← 将 PG plan → SQL 字符串（下推给 DuckDB）
  BeginForeignScan
    → GetPGDuckConnection()  ← 获取与 pgduck_server 的连接
  IterateForeignScan
    → send_prepared_statement() / fetch_more_data()
    → ExecStoreHeapTuple()   ← TupleTableSlot 填充
         ↕ PostgreSQL wire protocol（本地 port 5332）
pgduck_server 独立进程（SDK 层）
  DuckDB + duckdb-iceberg
    iceberg_scan() → Avro 元数据遍历 → 向量化 Parquet 读取
```

**双进程原因**：PG 多进程架构（每连接一 worker）使多线程 DuckDB 嵌入不安全，故将 DuckDB 拆为独立进程。

#### C 扩展关键文件

```
pg_lake_table/src/fdw/
├── pg_lake_table.c        # FdwRoutine 注册 + BeginForeignScan / IterateForeignScan
├── data_file_pruning.c    # 文件级 predicate pushdown
├── deparse.c              # PG plan → SQL（下推给 DuckDB）
└── partition_transform.c  # 分区变换（identity/bucket/truncate/year/month/day/hour）

pg_lake_iceberg/src/
├── iceberg/               # Iceberg v2 JSON 元数据解析（C）
├── avro/                  # Avro manifest 读取（C + libavro）
├── rest_catalog/          # REST Catalog 客户端（C）
└── object_store_catalog/  # PG 系统表作为 Iceberg Catalog
```

#### 扫描状态（C）与 fdw_private 编码

```c
typedef struct PgLakeScanState {
    Relation          rel;
    TupleDesc         tupdesc;
    char             *query;           /* 下推给 DuckDB 的 SQL 字符串 */
    List             *retrieved_attrs;
    PGDuckConnection *conn;            /* pgduck_server 连接 */
    HeapTuple        *tuples;
    int               num_tuples;
    MemoryContext     batch_cxt;
    PgLakeScanSnapshot *scanSnapshot;
} PgLakeScanState;

typedef enum {
    FdwScanPrivateSelectSql,       /* DuckDB SQL 字符串 */
    FdwScanPrivateRetrievedAttrs,  /* 投影列号 */
    FdwScanPrivateRteList,
    FdwScanPrivateRestrictions,    /* 谓词列表 */
    FdwScanPrivateRelations,
} FdwScanPrivateIndex;

/* GetForeignPlan 编码，BeginForeignScan 解码 */
fdw_private = list_make5(sql_string, retrieved_attrs, rte_list, restrictions, relations);
char *sql = strVal(list_nth(fdw_plan->fdw_private, FdwScanPrivateSelectSql));
```

#### PostgreSQL 作为 Iceberg Catalog（pg_lake 特色设计）

- `CREATE TABLE ... USING iceberg` 触发 DDL hook，将快照/元数据指针写入 PG 系统表
- 查询时从本地系统表解析 manifest 路径，无需外部 Catalog 服务
- 通过 PG MVCC 实现 Iceberg 事务 ACID 语义，对外暴露 REST 接口实现跨引擎互操作

**优缺点**：C 扩展层与本模块需求最贴近（`pg_lake_table.c` FdwRoutine 注册、`pg_lake_iceberg` manifest C 解析可直接参考）；PG-native catalog。但双进程增加运维复杂度，DuckDB sidecar 是黑盒依赖。

### 2.2 supabase/wrappers（Rust FDW + iceberg-rust SDK）

**GitHub**: https://github.com/supabase/wrappers · 源码路径 `wrappers/src/fdw/iceberg_fdw/`  
**框架**: pgrx（Rust 编写 PG 扩展）· **SDK 层**: apache/iceberg-rust

#### 文件结构与分层

```
iceberg_fdw/
├── iceberg_fdw.rs   # IcebergFdw 结构体 + ForeignDataWrapper trait  ← FDW 层
├── pushdown.rs      # PG quals → iceberg-rust Predicate 转换         ← FDW 层
├── mapper.rs        # Iceberg 类型 → PostgreSQL Cell 映射             ← FDW 层
└── writer.rs        # INSERT 支持
```

#### 核心结构与 begin/iter scan 流程

```rust
pub(crate) struct IcebergFdw {
    rt: Runtime,                            // tokio 运行时（同步包装 SDK 异步调用）
    catalog: Box<dyn Catalog>,              // SDK Catalog（REST/S3Tables/...）
    stream: Option<ArrowRecordBatchStream>, // SDK 返回的 Arrow 批次流
    row_data: VecDeque<Vec<Option<Cell>>>,  // FDW 层：当前批次行缓存
    tgt_cols: Vec<Column>,
    ...
}

// begin_scan：FDW 层调用 SDK
// → catalog.load_table() → table.scan().select().with_filter().build()
// → rt.block_on(scan.to_arrow()) → 存入 self.stream

// iter_scan：FDW 层消费 SDK 输出
// → row_data 非空则取一行；否则从 stream 取下一 RecordBatch
// → mapper.rs 将 Arrow 列转 Vec<Option<Cell>> → 填充 pgrx Row
```

#### 谓词下推（pushdown.rs：quals → SDK Predicate）

| PG Qual 操作符 | iceberg-rust Predicate |
|--------------|------------------------|
| `= / < / <= / > / >=` | 对应比较谓词 |
| `<>` | `not_equal_to` |
| `IS NULL / IS NOT NULL` | `is_null / is_not_null` |
| `~~` (LIKE，前缀) | `starts_with` |
| `IN / NOT IN` | `is_in / is_not_in` |

限制：仅 AND 组合；OR 不下推；LIKE 仅前缀。

**优缺点**：pgrx 提供安全 Rust-PG 桥接；谓词下推较完整。但 `block_on` 同步包装有开销，pgrx 与 PG 版本耦合。

### 2.3 Greenplum Tea（闭源 C++ FDW + iceberg-cxx SDK）

Tea 是 Greenplum Iceberg 集成扩展，**FDW 层闭源**，iceberg-cxx 作为 SDK 层独立开源。根据 iceberg-cxx 仓库示例，推断 FDW 层结构：

```
BeginForeignScan（FDW 层，闭源）
  HiveCatalog::LoadTable()               → SDK Catalog 查询
  ice_tea::GetScanMetadata(              → SDK 文件规划（全部元数据遍历）
      fs, metadata_location, schema_fn,
      stats_filter, threads_num, ...)
  → ScanMetadata（DataEntry 列表 + delete 信息）存入 fdw_state

IterateForeignScan（FDW 层，闭源）
  ParquetFileReader → RowGroupReaderWithRowNumber  → SDK 数据读取
  → ArrowBatchWithRowPosition（含行号，用于 position delete）
  → apply position/equality delete
  → RecordBatch → TupleTableSlot                  → FDW 层类型转换
```

Tea 是目前已知的唯一生产级 C++ Iceberg FDW，FDW 层闭源但 SDK 层（iceberg-cxx）提供了 C++ FDW 实现的最直接 SDK 参考。

```cpp
ReaderOptions opts;
opts.path    = task->data_file()->file_path();
opts.io      = file_io;
opts.filter  = task->residual_filter();

auto reader = ReaderFactoryRegistry::Open(FileFormatType::kParquet, opts);
while (true) {
    Result<std::optional<ArrowArray>> batch = reader->Next();
    if (!batch.has_value()) break;
    // FDW 层：将 ArrowArray（C Data Interface）→ TupleTableSlot
}
```

| | 支持 | 不支持（Roadmap） |

#### 主扫描 API

```cpp
namespace iceberg::ice_tea {

// 一次调用完成全部元数据遍历，对应 FDW GetForeignPaths + GetForeignPlan 阶段的 SDK 工作
arrow::Result<ScanMetadata> GetScanMetadata(
    std::shared_ptr<arrow::fs::FileSystem> fs,
    const std::string&                     metadata_location,
    std::function<bool(iceberg::Schema&)>  use_avro_reader_schema,
    std::shared_ptr<filter::StatsFilter>   stats_filter,
    uint32_t threads_num,
    const GetScanMetadataConfig& config,
    std::shared_ptr<ILogger> logger

struct ScanMetadata {
    std::shared_ptr<Schema> schema;
    std::vector<Partition>  partitions;  // 每个分区的 DataEntry + delete 文件列表
};

struct DataEntry {
    std::string  path;
    std::vector<Segment> parts;              // 分段读取范围

};

}
```

#### Parquet 读取（输出 Arrow C++ RecordBatch，需链接 libarrow.so）

```cpp
ParquetFileReader reader(fs, data_entry.path);
reader.Open();
RowGroupReaderWithRowNumber rg_reader = reader.GetRowGroupReader(row_group_idx);
while (auto item = rg_reader.Next()) {
    // item.batch:            std::shared_ptr<arrow::RecordBatch>
    // item.first_row_number: 该 batch 起始行全局行号（position delete 必须）
}
```

与 iceberg-cpp 不同：输出 Arrow C++ RecordBatch（非 C Data Interface），**强依赖 libarrow.so**。

**谓词下推限制**：`StatsFilter` 仅做 manifest 层（文件列统计）裁剪，**不支持 manifest list 层的分区摘要剪枝**（partition pruning 缺失）。Catalog 支持：仅 HMS + Nessie，**不支持 REST Catalog**。

**优点**：C++20（比 iceberg-cpp 要求低）；实战驱动（Greenplum 实际生产）；position delete 含行号附带；支持 DV（v3 预备）。  
**缺点**：非官方；Arrow C++ 强依赖（v15.0.2 固定）；无分区层剪枝；无 REST Catalog；滚动 main，无版本号。

## 4. 实现路径技术细节

### 4.1 FDW 钩子：每个 Hook 的 FDW 层 vs SDK 层职责

| FDW Hook | FDW 层职责 | SDK 层职责 |
|----------|-----------|-----------|
| `GetForeignRelSize` | 填 `baserel->rows / width`（代价估算） | manifest `record_count` 累加 |
| `GetForeignPaths` | 传递 quals；调用 SDK 分区剪枝；候选路径加入 `add_path()` | manifest list → 分区摘要 × 谓词 → 过滤 manifest 文件 |
| `GetForeignPlan` | 调用 SDK 文件裁剪；FileScanTask 列表 + 投影列 + 残差谓词编码进 `fdw_private` | manifest 层 → 列 min/max × 谓词 → 产出最终 FileScanTask 列表 |
| `BeginForeignScan` | 从 `fdw_private` 解码文件列表；初始化 OBS/S3 连接；分配 `MemoryContext` / FastAllocator | 打开第一个 Parquet reader（`Open()` / `FileReaderBuilder`） |
| `IterateForeignScan` | 取当前批次一行 → `TupleTableSlot`；批次耗尽切换下一批；文件耗尽切换下一 task；全部结束返回空 slot | `reader->Next()` → `ArrowArray` / `RecordBatch`；行组读取 |
| `ReScanForeignScan` | 重置 task 游标和批次游标 | 重新打开第一个 Parquet reader |
| `EndForeignScan` | 关闭 reader；关闭 OBS 连接；`MemoryContextDelete(batch_cxt)` | `reader->Close()` / 析构 |

**fdw_private 编码建议**（本模块）：FileScanTask 列表（文件路径、投影 field_id、残差谓词）+ schema_id，参考 pg_lake `FdwScanPrivateIndex` 模式。

### 4.2 数据类型：Iceberg → Arrow → PostgreSQL

| Iceberg 类型 | Arrow 类型 | PG OID | 转换要点 |
|------------|-----------|--------|---------|
| `boolean` | BOOL | BOOLOID | `BoolGetDatum()` |
| `integer` | INT32 | INT4OID | `Int32GetDatum()` |
| `long` | INT64 | INT8OID | `Int64GetDatum()` |
| `float / double` | FLOAT / DOUBLE | FLOAT4/8OID | `Float4/8GetDatum()` |
| `decimal(P,S)` | DECIMAL128 | NUMERICOID | `ToString(scale)` → `numeric_in()`，见下 |
| `date` | DATE32 | DATEOID | days since 1970 → days since 2000，**偏移 10957** |
| `time` | TIME64_US | TIMEOID | µs since midnight，**直接使用** |
| `timestamp` | TIMESTAMP_US | TIMESTAMPOID | µs since 1970 → µs since 2000，**偏移 946684800000000LL**，见下 |
| `timestamptz` | TIMESTAMP_US_TZ | TIMESTAMPTZOID | 同上偏移，已含 UTC |
| `string` | STRING / LARGE_STRING | TEXTOID | `cstring_to_text_with_len()` |
| `uuid` | FIXED_SIZE_BINARY(16) | UUIDOID | 16 字节直拷 |
| `binary / fixed` | BINARY / FIXED_SIZE_BINARY | BYTEAOID | `SET_VARSIZE()` 包裹 |
| `list<T>` | LIST | 数组 OID | `construct_md_array()` |
| `map<K,V>` / `struct` | MAP / STRUCT | JSONBOID | `pushJsonbValue()` 递归构造 |

**Timestamp 纪元转换**（最易出错）：

```c
#define EPOCH_DIFF_USECS  ((int64_t)(2451545 - 2440588) * 86400000000LL)  /* = 946684800000000 */
#define EPOCH_DIFF_DAYS   (2451545 - 2440588)                              /* = 10957 */

static Datum arrow_timestamp_to_pg(int64_t arrow_ts_us) {
    return TimestampGetDatum(arrow_ts_us - EPOCH_DIFF_USECS);
}
static Datum arrow_date_to_pg(int32_t arrow_days) {
    return DateADTGetDatum((DateADT)(arrow_days - EPOCH_DIFF_DAYS));
}
```

**DECIMAL128 转 numeric**：

```c
arrow::Decimal128 val = arr->Value(i);
std::string s = val.ToString(scale);   // "123.45"
return DirectFunctionCall3(numeric_in, CStringGetDatum(s.c_str()),
    ObjectIdGetDatum(InvalidOid), Int32GetDatum(make_typmod(precision, scale)));
```

### 4.3 谓词下推三层架构

```
PostgreSQL WHERE 谓词
    │  FDW 层：quals 解析，区分可下推 / 不可下推（基础标量比较，非函数调用，非列-列）
    ▼
    Layer 1：manifest list 分区摘要剪枝（GetForeignPaths 阶段）
      SDK：manifest list Avro 中每条目的 partition_summary（lower/upper bound）
      适用：identity/bucket/truncate/year/month/day/hour 分区列
      参考：pg_lake partition_transform.c，iceberg-cpp ManifestEvaluator
    ▼
    Layer 2：manifest 文件统计裁剪（GetForeignPlan 阶段）
      SDK：manifest Avro 中每数据文件条目的列 lower_bounds / upper_bounds
      适用：任意列（含非分区列）
      参考：iceberg-cxx StatsFilter，iceberg-cpp inclusive_metrics_evaluator
    ▼
    Layer 3：Parquet 行组统计过滤（IterateForeignScan 打开文件时）
      SDK/Arrow：Parquet footer 中每行组的 min/max statistics
      由 Arrow Parquet reader 内部处理
      参考：parquet_fdw extract_rowgroup_filters()
```

### 4.4 Arrow RecordBatch → TupleTableSlot 转换

**策略 A：按行逐列提取**（parquet_fdw DefaultParquetReader，行优先）：

```cpp
bool populate_slot(TupleTableSlot *slot, arrow::RecordBatch *batch, int row_idx) {
    for (int col = 0; col < num_target_cols; col++) {
        arrow::Array *arr = batch->column(col).get();
        int attno = target_attno[col];
        if (arr->IsNull(row_idx)) {
            slot->tts_isnull[attno-1] = true;
        } else {
            slot->tts_values[attno-1] = read_primitive_type(arr, typinfo[col], row_idx);
            slot->tts_isnull[attno-1] = false;
        }
    }
    ExecStoreVirtualTuple(slot);
    return true;
}
```

**策略 B：整批列转换后逐行消费**（parquet_fdw CachingParquetReader，列优先）：批次到来时预先将每列整批转为 `Datum[]`，`IterateForeignScan` 只从缓存取行，减少 Arrow API 调用次数。

**FastAllocator 内存管理**（parquet_fdw 模式）：

```cpp
class FastAllocator {
    // 1MB 块预分配，批次粒度统一释放，避免逐行 palloc 开销
    void *palloc(size_t size);   // 从当前 segment 顺序分配
    void reset();                // 批次结束后整体 pfree
};
// IterateForeignScan 在批次边界调用 reset()
```

**Arrow C Data Interface 直读**（iceberg-cpp 路径，不链接 Arrow C++ so）：

```c
// 标量列：buffer[0] = validity bitmap，buffer[1] = 值数组
const int32_t *vals  = (const int32_t *)c_array.buffers[1];
const uint8_t *nulls = (const uint8_t *)c_array.buffers[0];
for (int i = 0; i < c_array.length; i++) {
    bool isnull = nulls ? !((nulls[i/8] >> (i%8)) & 1) : false;
    slot->tts_values[attno-1] = isnull ? (Datum)0 : Int32GetDatum(vals[i + c_array.offset]);
    slot->tts_isnull[attno-1] = isnull;
}
```

### 4.5 C/C++ 实现参考路径与建议

#### 推荐分层

```
iceberg_fdw.c / .cpp                     ← FDW 层（纯 C + C++17，兼容 GaussDB）
  FdwRoutine 注册   参考：parquet_fdw.c
  GetForeignRelSize  → SDK：manifest record_count 累加
  GetForeignPaths   → SDK：manifest list 分区摘要剪枝
  GetForeignPlan    → SDK：manifest 列统计文件裁剪 → FileScanTask → fdw_private
                    参考：pg_lake FdwScanPrivateIndex 编码
  BeginForeignScan  → SDK：打开 Parquet reader；初始化 batch_cxt / FastAllocator
  IterateForeignScan → SDK：Next() 取 batch → Arrow → TupleTableSlot
                    参考：parquet_fdw parquet_impl.cpp / reader.cpp
  EndForeignScan    → 关闭 reader，MemoryContextDelete

iceberg_metadata.[c/cpp]                 ← SDK 层：Iceberg 格式解析
  IcebergReadTableMetadata()             参考：pg_lake read_table_metadata.c
  IcebergReadManifestList()              参考：pg_lake avro/ + read_manifest.c
  IcebergReadManifest() + EvalStats()    参考：iceberg-cxx StatsFilter

iceberg_parquet.[c/cpp]                  ← SDK 层：Parquet 数据读取
  IcebergParquetReaderOpen()             parquet::arrow::FileReaderBuilder
  IcebergParquetNextBatch() → ArrowArray 参考：iceberg-cpp Reader::Next()
  IcebergArrowBatchToSlot()              参考：parquet_fdw read_primitive_type()

iceberg_catalog.[c/cpp]                  ← Catalog 集成
  IcebergCatalogOps（函数指针接口，解耦 Catalog 后端）
  IcebergSysTableCatalog                 参考：pg_lake object_store_catalog/
  IcebergRestCatalog                     参考：pg_lake rest_catalog/
```

#### SDK 选型与编译风险

| 层次 | 推荐 | 编译要求 | 风险 |
|------|------|---------|------|
| Iceberg 元数据解析 | pg_lake_iceberg C 代码移植 | C99 | **低**，已在 PG 环境验证 |
| Iceberg 元数据解析（备选） | iceberg-cxx SDK | C++20，GCC 11+ | **中**，需确认工具链 |
| Iceberg 元数据解析（备选） | iceberg-cpp SDK | **C++23，GCC 14+** | **高**，与 GaussDB 编译环境冲突 |
| Parquet 数据读取 | Arrow C++ parquet 模块 | C++17，GCC 9+ | **低**，成熟稳定 |
| S3/OBS 文件访问 | Arrow S3FileSystem 或 S3RandomAccessFile | C++17 | **低**，参考 parquet_s3_fdw |

**结论**：主体用 C，Parquet 读取用 C++17，元数据解析移植 pg_lake C 代码，不以 iceberg-cpp/iceberg-cxx 为编译期依赖。
