## 0. 背景：FDW 在湖仓架构中的定位

### 0.1 湖仓架构中的 FDW 场景

在 Gauss Vector 湖仓集成方案中，FDW 模块承担的职责是：

```
┌──────────────────────────────────────────┐
│  GaussDB / openGauss 查询引擎             │
│    SELECT * FROM iceberg_tbl WHERE ...   │
├──────────────────────────────────────────┤
│  Iceberg FDW  ← 本模块（C/C++ 实现）      │
│   · Foreign Scan: 遍历 Iceberg 元数据树   │
│   · Predicate Pushdown: WHERE 条件下推    │
│   · Column Projection: 只读目标列         │
├──────────────────────────────────────────┤
│  Iceberg 元数据层（对象存储）             │
│   metadata.json → manifest list → manifests → Parquet │
├──────────────────────────────────────────┤
│  对象存储（OBS / S3）                     │
│   .parquet 数据文件                       │
└──────────────────────────────────────────┘
```

Catalog 部分（表名 → metadata.json 路径的解析）由数据库系统表/系统函数承担，FDW 模块接收已解析的 metadata 路径，负责完成后续的元数据遍历和数据读取。

### 0.2 Iceberg 元数据遍历路径（扫描必经之路）

任何 Iceberg FDW 都必须遍历以下链路：

```
Catalog (table name → metadata.json)
   │
   ▼
metadata.json          ← JSON，含当前 snapshot_id
   │
   ▼
manifest-list.avro     ← Avro，每条目一个 manifest 文件路径 + 分区摘要
   │  (分区剪枝 partition pruning 发生在此层)
   ▼
manifest-N.avro        ← Avro，每条目一个数据文件路径 + 列级 min/max 统计
   │  (文件级 predicate pushdown 发生在此层)
   ▼
data-file.parquet      ← 实际列式数据
      (行组级 row group pushdown 发生在此层，由 Parquet reader 处理)
```

上述三级下推（分区剪枝 → 文件裁剪 → 行组裁剪）是所有成熟实现的标配。

#### Reader 接口（Arrow C Data Interface 输出）

**v0.2.0 实际数据读取路径**（注意：`FileScanTask::ToArrowArrayReader()` **不存在**）：

```cpp
// 正确路径：通过 ReaderFactoryRegistry 打开 Parquet 文件
ReaderOptions opts;
opts.path       = task->data_file()->file_path();
opts.io         = file_io;                          // ArrowFileSystemFileIO
opts.projection = projected_schema;                 // Schema 投影
opts.filter     = task->residual_filter();          // 残差谓词

// ReaderProperties 可调参数
ReaderProperties props;
props.Set(ReaderProperties::kBatchSize, int64_t{8192});  // 默认 4096

auto reader = ReaderFactoryRegistry::Open(FileFormatType::kParquet, opts);
reader->Open(opts);

while (true) {
    Result<std::optional<ArrowArray>> maybe_batch = reader->Next();
    if (!maybe_batch.has_value()) break;   // 文件结束
    ArrowArray batch = std::move(*maybe_batch);

    // v2 delete 文件处理（如果 task->delete_files() 非空）
    ArrowSchema schema = reader->Schema().ValueOrDie();
    AliveRowSelection alive = delete_filter->ComputeAliveRows(schema, batch);
    // 仅处理 alive.indices 中的行

    // 将 ArrowArray（C Data Interface）导入为 C++ Arrow 对象或直接操作缓冲区
    // arrow::ImportRecordBatch(&batch, &schema) → arrow::RecordBatch
}
```

`Reader::Next()` 内部使用 `parquet::arrow::FileReader`，调用 `record_batch_reader_->Next()` → `ProjectRecordBatch()` → `arrow::ExportRecordBatch()`，最终以 `ArrowArray` C Data Interface 形式输出。

#### v0.2.0 能力与 Roadmap

**已支持**：
- 完整 v2 扫描计划（含 delete file 处理：position + equality delete）
- append 写入（FastAppend snapshot 事务）
- Schema evolution（add/delete/update/move）
- 完整 REST Catalog 客户端（namespace + table CRUD，StageCreateTable，RegisterTable）
- 表达式系统：Predicate/Literal，manifest 评估器，残差评估器
- Arrow C Data Interface 输出（无需链接完整 Arrow C++ 动态库）

**不支持（roadmap）**：
- Puffin 统计写入
- IncrementalAppend/ChangelogScan（v0.4 roadmap）
- HMS/Glue Catalog（v0.3+ roadmap）
- Iceberg v3 特性

**优缺点**：

| | 评价 |
|--|------|
| 优点 | Apache 官方出品，与规范同步最及时；Arrow C Data Interface 输出无额外 so 依赖；表达式/谓词系统完整；DeleteFilter API 覆盖 v2 delete |
| 缺点 | **C++23 要求高**（GCC 14+），与多数数据库系统的编译环境（GCC 11-12）冲突；v0.2.0 仍较新；Catalog 支持仅 REST + 内存（无 HMS/JDBC） |

#### 与 Tea/Greenplum FDW 的关系

Tea（Greenplum Iceberg 扩展）是**闭源的**，iceberg-cxx 作为其独立 C++ 库层开源。根据 `streams/main.cpp` 示例，Tea FDW 层预计的工作流：

```
[Tea FDW BeginForeignScan]
  HiveCatalog::LoadTable() → metadata_location
  ice_tea::GetScanMetadata(fs, metadata_location, ..., stats_filter, ...)
      → ScanMetadata（含所有 DataEntry + delete 信息）
  存入 FDW scan state

[Tea FDW IterateForeignScan]
  对当前 DataEntry 的当前 batch：
  ParquetFileReader → RowGroupReaderWithRowNumber → ArrowBatchWithRowPosition
  Apply position/equality delete
  ArrowBatchWithRowPosition.batch → PostgreSQL TupleTableSlot
```

| 类别 | 支持 | 不支持 |
|------|------|--------|

            return TimestampGetDatum(ts - 946684800000000LL);

            arrow::Decimal128 d = std::static_pointer_cast<arrow::Decimal128Array>(array)->Value(i);

## 5. FDW 执行模型与 Iceberg 扫描路径的映射

### 5.1 PostgreSQL FDW Hook 全集

```c
typedef struct FdwRoutine {
    /* === 规划阶段（Planner，一次性） === */
    GetForeignRelSize_function    GetForeignRelSize;   // 估算行数/宽度（统计信息）
    GetForeignPaths_function      GetForeignPaths;     // 生成候选扫描路径（并行/串行）
    GetForeignPlan_function       GetForeignPlan;      // 生成最终扫描计划节点

    /* === 执行阶段（Executor，每次查询） === */
    BeginForeignScan_function     BeginForeignScan;    // 初始化扫描状态
    IterateForeignScan_function   IterateForeignScan;  // 逐行/批返回
    ReScanForeignScan_function    ReScanForeignScan;   // 重置扫描（嵌套循环时）
    EndForeignScan_function       EndForeignScan;      // 释放资源

    /* === 写入（可选） === */
    BeginForeignModify_function   BeginForeignModify;
    ExecForeignInsert_function    ExecForeignInsert;
    ExecForeignDelete_function    ExecForeignDelete;
    ExecForeignUpdate_function    ExecForeignUpdate;
    EndForeignModify_function     EndForeignModify;

    /* === 并行扫描（可选，P4 阶段） === */
    IsForeignScanParallelSafe_function  IsForeignScanParallelSafe;
    EstimateDSMForeignScan_function     EstimateDSMForeignScan;
    InitializeDSMForeignScan_function   InitializeDSMForeignScan;
    ReInitializeDSMForeignScan_function ReInitializeDSMForeignScan;
    InitializeWorkerForeignScan_function InitializeWorkerForeignScan;
    ShutdownForeignScan_function        ShutdownForeignScan;
} FdwRoutine;
```

### 5.2 Hook 与 Iceberg 操作的对应关系（含各实现的处理策略对比）

| FDW Hook | Iceberg 操作 | iceberg-cpp 方案 | iceberg-cxx 方案 | pg_lake 方案 |
|----------|-------------|-----------------|-----------------|-------------|
| `GetForeignRelSize` | 读取 metadata.json，估算行数 | `PlanFiles()` + `estimated_row_count()` | 无（不支持统计） | manifest 中的 `record_count` 累加 |
| `GetForeignPaths` | 分区剪枝（manifest list 层） | manifest list 评估器过滤 | `GetScanMetadata()` 中 StatsFilter | partition_transform.c |
| `GetForeignPlan` | 文件裁剪（manifest 层）+ fdw_private 编码 | residual filter + 文件列表序列化入 fdw_private | DataEntry 列表序列化 | data_file_pruning.c，SQL 字符串入 fdw_private |
| `BeginForeignScan` | 初始化 Reader，打开第一个文件 | `ReaderFactoryRegistry::Open(kParquet, opts)` | `ParquetFileReader::Open()` | `CreatePgLakeScanSnapshot()` + DuckDB 连接 |
| `IterateForeignScan` | 按批读取 Parquet → TupleTableSlot | `reader->Next()` → `ArrowArray` → slot | `rg_reader.Next()` → `RecordBatch` → slot | `send_prepared_statement()` → `ExecStoreHeapTuple()` |
| `EndForeignScan` | 关闭 Reader，释放连接 | `reader->Close()` | reader 析构 | `PQfinish(conn)` |

### 5.3 fdw_private 编码模式

规划阶段（`GetForeignPlan`）需要将 metadata 解析结果传递给执行阶段（`BeginForeignScan`）：

```c
/* pg_lake 的 FdwScanPrivateIndex 枚举示例 */
typedef enum {
    FdwScanPrivateSelectSql,       /* 下推给 DuckDB 的 SQL */
    FdwScanPrivateRetrievedAttrs,  /* 投影列号列表 */
    FdwScanPrivateRteList,         /* RTE 列表 */
    FdwScanPrivateRestrictions,    /* 谓词列表 */
    FdwScanPrivateRelations,       /* 参与关系 */
} FdwScanPrivateIndex;

/* GetForeignPlan 中编码 */
fdw_private = list_make5(
    makeString(sql),
    retrieved_attrs,
    rte_list,
    restrictions,
    relations
);

/* BeginForeignScan 中解码 */
PgLakeScanState *scanState = ...;
char *sql = strVal(list_nth(fdw_plan->fdw_private, FdwScanPrivateSelectSql));
```

对于本模块（不依赖 DuckDB），fdw_private 应编码 FileScanTask 列表（文件路径、投影字段、残差谓词等）。

### 5.4 数据类型：Iceberg → Arrow → PostgreSQL 映射

#### 基础类型映射

| Iceberg 类型 | Arrow 类型 | PostgreSQL OID | 转换注意 |
|------------|-----------|---------------|---------|
| `boolean` | `BOOL` | `BOOLOID` | 直接 `BoolGetDatum()` |
| `integer`（32位） | `INT32` | `INT4OID` | `Int32GetDatum()` |
| `long`（64位） | `INT64` | `INT8OID` | `Int64GetDatum()` |
| `float`（32位） | `FLOAT` | `FLOAT4OID` | `Float4GetDatum()` |
| `double`（64位） | `DOUBLE` | `FLOAT8OID` | `Float8GetDatum()` |
| `decimal(P,S)` | `DECIMAL128` | `NUMERICOID` | `Decimal128::ToString()` → `numeric_in()` |
| `date` | `DATE32` | `DATEOID` | Arrow days since 1970-01-01；PG days since 2000-01-01；偏移 = `10957` |
| `time` | `TIME64_US` | `TIMEOID` | Arrow µs since midnight；PG 同样 µs since midnight；**直接使用** |
| `timestamp` (无 tz) | `TIMESTAMP_US` | `TIMESTAMPOID` | **关键**：Arrow µs since 1970-01-01，PG µs since 2000-01-01，偏移 = `946684800000000LL` |
| `timestamptz` | `TIMESTAMP_US_TZ` | `TIMESTAMPTZOID` | 同上偏移，已含 UTC |
| `string` | `STRING` / `LARGE_STRING` | `TEXTOID` | `cstring_to_text_with_len()` |
| `uuid` | `FIXED_SIZE_BINARY(16)` | `UUIDOID` | 16 字节直拷 |
| `binary` | `BINARY` / `LARGE_BINARY` | `BYTEAOID` | `SET_VARSIZE()` 包裹 |
| `fixed(N)` | `FIXED_SIZE_BINARY(N)` | `BYTEAOID` | 同 binary |
| `list<T>` | `LIST` | 数组 OID（`get_array_type(elem_oid)`） | `construct_md_array()` |
| `map<K,V>` | `MAP` | `JSONBOID` | `pushJsonbValue()` 构造 |
| `struct<...>` | `STRUCT` | `JSONBOID` | 递归转为 JSONB |

#### Timestamp 纪元转换（关键）

```c
/* Arrow 使用 Unix epoch（1970-01-01），PostgreSQL 使用 2000-01-01 */
/* 偏移计算 */
#define POSTGRES_EPOCH_JDATE  2451545  /* 2000-01-01 Julian day */
#define UNIX_EPOCH_JDATE      2440588  /* 1970-01-01 Julian day */
#define EPOCH_DIFF_USECS  \
    ((int64_t)(POSTGRES_EPOCH_JDATE - UNIX_EPOCH_JDATE) * 86400000000LL)
/* = 10957 * 86400000000 = 946684800000000 µs */

static Datum
arrow_timestamp_to_pg(int64_t arrow_ts_us) {
    return TimestampGetDatum(arrow_ts_us - EPOCH_DIFF_USECS);
}

/* Date 类型（day 为单位） */
#define EPOCH_DIFF_DAYS  (POSTGRES_EPOCH_JDATE - UNIX_EPOCH_JDATE)  /* = 10957 */

static Datum
arrow_date_to_pg(int32_t arrow_days) {
    return DateADTGetDatum((DateADT)(arrow_days - EPOCH_DIFF_DAYS));
}
```

#### DECIMAL128 转 numeric

```c
static Datum
arrow_decimal_to_pg(const arrow::Decimal128Array *arr, int64_t i,
                    int32_t precision, int32_t scale) {
    arrow::Decimal128 val = arr->Value(i);
    std::string s = val.ToString(scale);        // "123.45"
    return DirectFunctionCall3(
        numeric_in,
        CStringGetDatum(s.c_str()),
        ObjectIdGetDatum(InvalidOid),
        Int32GetDatum(make_typmod(precision, scale))
    );
}
```

### 5.5 谓词下推：三层架构

```
PostgreSQL WHERE 谓词
    │
    ▼  [GetForeignPaths 阶段]
    ├─ Layer 1：manifest list 分区摘要剪枝（partition pruning）
    │    · 基于 manifest 条目中的 partition_summary（每列的 lower/upper bound）
    │    · 适用于分区列：identity / bucket / truncate / year / month / day / hour
    │    · 实现参考：pg_lake partition_transform.c，iceberg-cpp ManifestEvaluator
    │
    ▼  [GetForeignPlan 阶段]
    ├─ Layer 2：manifest 文件统计裁剪（file pruning）
    │    · 基于 manifest 条目中的 column_sizes / value_counts / null_value_counts
    │      / lower_bounds / upper_bounds（Iceberg 列统计，Avro 字节编码）
    │    · 适用于任意列，非分区列亦可
    │    · 实现参考：iceberg-cxx StatsFilter，iceberg-cpp inclusive_metrics_evaluator
    │
    ▼  [IterateForeignScan 阶段]
    └─ Layer 3：Parquet 行组统计过滤（row group pruning）
         · 基于 Parquet footer 中每个 row group 的 min/max statistics
         · 由 Arrow Parquet reader 处理（parquet::arrow::FileReader + RowGroupFilter）
         · 实现参考：parquet_fdw extract_rowgroup_filters()
```

**谓词可下推性判断**（典型实现）：

```cpp
// 仅基础标量比较谓词可下推；以下情况不下推：
// 1. 函数调用（f(col) = val）
// 2. 两侧都是列引用（col1 = col2）
// 3. 类型不兼容（PG typmod 与 Iceberg precision/scale 不匹配）
// 4. OR 组合（可选支持，iceberg-rust 不支持）
// 5. 子查询或参数化条件

bool is_pushdownable(const Qual &qual) {
    return qual.field_type == FieldType::COLUMN
        && qual.value_type == ValueType::CONSTANT
        && is_basic_comparison_op(qual.op)
        && !uses_or_combination(qual);
}
```

### 5.6 Arrow RecordBatch → TupleTableSlot 转换模式

两种主流策略（参考 parquet_fdw）：

#### 策略 A：按行逐列提取（DefaultParquetReader，行优先）

```cpp
// IterateForeignScan 调用，每次处理一行
bool populate_slot(TupleTableSlot *slot, arrow::RecordBatch *batch, int row_idx) {
    for (int col = 0; col < num_target_cols; col++) {
        int attno = target_attno[col];
        arrow::Array *arr = batch->column(col).get();
        if (arr->IsNull(row_idx)) {
            slot->tts_isnull[attno - 1] = true;
        } else {
            slot->tts_values[attno - 1] = read_primitive_type(arr, typinfo[col], row_idx);
            slot->tts_isnull[attno - 1] = false;
        }
    }
    ExecStoreVirtualTuple(slot);  // 标记 slot 已填充，不拷贝数据
    return true;
}
```

#### 策略 B：整批列转换（CachingParquetReader，列优先）

```cpp
// BeginForeignScan 时初始化列缓存
// 当批次到来时，先将每列的 Arrow Array 批量转换为 Datum 数组，
// 存储于 ColData { Datum *values; bool *nulls; int len; }
// IterateForeignScan 每次只从缓存取一行，不重复调用 Arrow API
ColData col_data[MAX_COLUMNS];

void cache_batch(arrow::RecordBatch *batch) {
    for (int col = 0; col < num_cols; col++) {
        auto arr = batch->column(col);
        col_data[col].len = batch->num_rows();
        for (int i = 0; i < batch->num_rows(); i++) {
            if (arr->IsNull(i)) {
                col_data[col].nulls[i] = true;
            } else {
                col_data[col].values[i] = convert_to_datum(arr, typinfo[col], i);
            }
        }
    }
}
```

#### 内存管理：FastAllocator（parquet_fdw 模式）

```cpp
class FastAllocator {
    // 预分配 1MB 内存段，在批次粒度上集中释放
    // 避免 palloc/pfree 逐行开销
    MemoryContext mctx;
    static const size_t SEGMENT_SIZE = 1024 * 1024;  // 1MB

    void *palloc(size_t size);          // 从当前 segment 顺序分配
    void reset();                       // 批次结束后整体 pfree，非逐行

    // 在 IterateForeignScan 批次边界处调用 reset()
    // 确保 Arrow Array / Datum 缓冲区只在批次内有效
};
```

### 5.7 Arrow C Data Interface 在 FDW 中的使用（iceberg-cpp 路径）

当使用 iceberg-cpp 的 `Reader::Next()` 返回 `ArrowArray`（C Data Interface）时，FDW 侧处理：

```c
/* 方式 1：通过 arrow::ImportRecordBatch 转为 C++ 对象 */
#include <arrow/c/bridge.h>

ArrowSchema c_schema;
ArrowArray  c_array;
reader->Schema(&c_schema);         // 获取 schema
reader->Next(&c_array);            // 获取一批数据

auto rb = arrow::ImportRecordBatch(&c_array, &c_schema).ValueOrDie();
// 之后走 parquet_fdw 的 populate_slot 路径

/* 方式 2：直接读 C Data Interface 缓冲区（零拷贝，不链接 Arrow C++）*/
// 对于标量列，buffer[0] 是有效性位图，buffer[1] 是值数组
const int32_t *vals = (const int32_t *)c_array.buffers[1];
const uint8_t *nulls = (const uint8_t *)c_array.buffers[0];
for (int i = 0; i < c_array.length; i++) {
    bool isnull = nulls ? !((nulls[i/8] >> (i%8)) & 1) : false;
    slot->tts_values[attno-1] = isnull ? (Datum)0 : Int32GetDatum(vals[i + c_array.offset]);
    slot->tts_isnull[attno-1] = isnull;
}
```

方式 1 代码更清晰但需要链接 Arrow C++ 库；方式 2 可以不链接任何 Arrow 库，但需要按 [Arrow C Data Interface 规范](https://arrow.apache.org/docs/format/CDataInterface.html) 手动处理各列类型（包括 validity bitmap, offset arrays for variable-length types 等）。

## 6. Catalog 实现形态分析

在本模块（Gauss Vector 湖仓 FDW）的背景下，Catalog 有以下几种实现形态：

### 6.1 形态一：外部 REST Catalog（最解耦）

```
FDW → REST Catalog（Polaris/Nessie/Lakekeeper）→ metadata.json 路径
```

- FDW 通过 `OPTIONS (catalog_type 'rest', catalog_uri '...')` 连接外部 REST Catalog
- **优点**：FDW 逻辑最简单；Catalog 独立演进；标准接口
- **缺点**：引入外部网络依赖；每次规划都有网络延迟；无法利用数据库事务语义

### 6.2 形态二：数据库系统表作为 Catalog（pg_lake 模式）

```
FDW → GaussDB 系统表（iceberg_tables, iceberg_snapshots...）→ metadata.json 路径
```

- FDW 直接查询本数据库内的系统表获取 metadata 路径
- Catalog 的写入由系统函数（DDL 钩子）完成
- **优点**：零网络延迟；与数据库事务天然集成；可充分利用 GaussDB 自身的 MVCC
- **缺点**：Catalog 与数据库耦合；跨引擎互操作需要额外的 REST 接口层
- **适用**：本模块（Catalog metadata 以系统表形式实现）最贴近此形态

### 6.3 形态三：SDK/插件化 Catalog

```
FDW → Catalog 插件 DSO（.so）→ Catalog 后端（JDBC/HMS/REST/系统表）
```

- Catalog 逻辑封装为可插拔的动态库，FDW 通过统一接口调用
- 类似 iceberg-cpp 的 `Catalog` 抽象接口模式
- **优点**：Catalog 实现可替换；FDW 代码稳定
- **缺点**：接口设计复杂度高；DSO 生命周期管理

### 6.4 形态对比

| 形态 | 延迟 | 事务集成 | 跨引擎 | 实现复杂度 |
|------|------|---------|--------|-----------|
| REST Catalog | 高（网络） | 弱 | 强 | 低 |
| 系统表 Catalog | 极低（本地） | 强（MVCC） | 需额外层 | 中 |
| 插件化 Catalog | 中 | 中 | 中 | 高 |

**结论**：本模块最适合"系统表 Catalog + 可选 REST Catalog 适配层"的混合形态，本地读走系统表，对外互操作走 REST。

## 7. C/C++ 实现的参考路径与建议

### 7.1 推荐技术栈

| 层次 | 推荐选项 | 备注 |
|------|---------|------|
| Iceberg 元数据层（JSON + Avro） | pg_lake_iceberg 的 C 解析代码 | 直接可用；已在 PG 环境验证；C 语言无 ABI 问题 |
| Iceberg 元数据层（备选） | iceberg-cpp（若 GCC 14+ 可用） | 官方实现，表达式/manifest 评估器完整 |
| Parquet 读取层 | Apache Arrow C++ parquet 模块 | C++17 即可，成熟稳定，Arrow v12+ 支持 S3 FileSystem |
| S3/OBS 文件访问 | Arrow S3FileSystem 或 S3RandomAccessFile | 参考 parquet_s3_fdw 的桥接模式 |
