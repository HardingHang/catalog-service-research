# GaussVector - Iceberg FDW 层详细设计

## 1. 设计背景

### 1.1 设计目标与范围

实现 Iceberg 外表只读扫描的 FDW 层：执行器查询外表时，规划回调解析 Catalog 得到表身份与数据文件描述，生成 `ForeignScan` 计划节点；执行回调据此扫描并逐行返回元组。

| 项目 | 范围 |
| --- | --- |
| 形态 | 仅行式 tuple 路径 |
| 逻辑结构 | 二级命名 `namespace.table_name`，不支持多级嵌套 namespace |
| Catalog 后端 | `pg_native`（GaussVector `iceberg_catalog.*` 元信息表） |
| 回调函数 | `GetForeignRelSize`、`GetForeignPaths`、`GetForeignPlan`、`BeginForeignScan`、`IterateForeignScan`、`EndForeignScan`、`ReScanForeignScan`、`ExplainForeignScan` |

### 1.2 整体架构

FDW 层分规划期与执行期两条回调路径，二者通过 `ForeignScan` 节点上的 `fdw_private` 传递数据。规划期读 Catalog 元信息表，执行期由 reader 读对象存储中的数据文件。

```
SQL / 执行器：SELECT ... FROM <iceberg 外表>
  │
  ├─ 规划期回调
  │    GetForeignRelSize    估行
  │    GetForeignPaths      生成访问路径
  │    GetForeignPlan       解析 Catalog + PlanFiles → 编码 fdw_private → 生成 ForeignScan
  │      │
  │      ├─→ Catalog 解析（只读，SPI）：iceberg_catalog.tables / snapshots
  │      │     （当前指针 + snapshot 摘要，全为普通列；不含 manifest/data 明细）
  │      │
  │      └─→ PlanFiles：snapshots.manifest_list → manifest → data file
  │             （读对象存储，产出 FileScanTask；产出时机见 §2.3）
  │
  │   fdw_private 随 ForeignScan 节点传给执行期
  │
  └─ 执行期回调
       BeginForeignScan     解码 fdw_private，建立扫描态与内存上下文
       IterateForeignScan   批缓存，逐行返回 tuple
       EndForeignScan       释放 reader 与内存上下文
       ReScanForeignScan    重置游标后重扫
         │
         └─→ reader（不透明句柄，下半层）：FileScanTask → *.parquet / delete → Arrow → tuple
```

### 1.3 FdwRoutine 注册

handler 用 `makeNode(FdwRoutine)` 创建结构（未赋值字段自动为 `NULL`），逐字段赋回调指针：

| 字段 | 赋值 | 说明 |
| --- | --- | --- |
| `GetForeignRelSize` / `GetForeignPaths` / `GetForeignPlan` | 是 | 规划三回调（§3.1–3.3） |
| `BeginForeignScan` / `IterateForeignScan` / `EndForeignScan` | 是 | 扫描生命周期（§3.4–3.6） |
| `ReScanForeignScan` | 是（最小实现） | 子计划重扫（§3.6） |
| `ExplainForeignScan` | 是 | EXPLAIN 附加输出（§3.7） |
| Modify 族、Join/Upper 下推、采样、内存统计等 | `NULL` | 不实现 |

### 1.4 OPTIONS 配置与校验

每张外表归属一个 SERVER，SERVER 绑定 FOREIGN DATA WRAPPER。catalog 后端配置为 server 下所有外表共享，置于 server；表身份逐表声明，置于 table。

| 层级 | OPTION | 必需 | 用途 |
| --- | --- | --- | --- |
| server | `catalog_kind` | 否（默认 `pg_native`） | Catalog 后端 |
| server | `catalog_schema` | 否（默认 `iceberg_catalog`） | 元信息表所在 schema |
| table | `namespace` | 是 | Iceberg 表所属 namespace（对应 DB schema） |
| table | `table_name` | 是 | Iceberg 表名 |

## 2. 数据结构

同一份扫描所需信息，在 DDL、规划、执行三阶段由不同结构承载，后一阶段的数据由前一阶段生成；规划回调与执行回调不共享内存，只能通过 `fdw_private` 传递。

| 阶段 | 数据 | 存储位置 | 生成者 | 使用者 |
| --- | --- | --- | --- | --- |
| DDL | OPTIONS | 系统目录（`pg_foreign_table` / `pg_foreign_server`） | `CREATE ... OPTIONS`，validator 校验 | 规划回调 |
| 规划 | `fdw_private` | `ForeignScan` 计划节点（可 `copyObject`） | `GetForeignPlan` | 执行回调 |
| 执行 | `IcebergScanState` | 进程内存（`node->fdw_state`） | `BeginForeignScan` | `Iterate` / `End` |

### 2.1 `fdw_private` 编码

按固定枚举顺序装配一个可序列化 `List`：

```c
enum IcebergScanPrivateIndex {
    IcebergPrivFileScanTasks,   /* 数据文件扫描描述（FileScanTask）列表 */
    IcebergPrivRetrievedAttrs,  /* 投影列属性号 List<int> */
};
```

- **`IcebergPrivFileScanTasks`**：本次扫描要读的数据文件描述列表（内容与产出时机见 §2.3）。
- **`IcebergPrivRetrievedAttrs`**：需读取回填的外表列属性号（attno），决定 reader 列裁剪与 tuple 填充范围。

局部谓词不进 `fdw_private`：它在 `make_foreignscan` 时作为节点 qual 列传入，由执行器对每行自动重过滤。`field_id` 也不在 FDW 层——按 `field_id` 对应文件列到表列是 reader 的工作（§4.3）。

### 2.2 `IcebergScanState` 执行态

```c
typedef struct IcebergScanState {
    Relation        rel;
    TupleDesc       tupdesc;
    List           *fileScanTasks;   /* 解码自 fdw_private */
    List           *retrievedAttrs;

    void           *reader;          /* 取数 reader 句柄；FDW 层不关心其内部实现 */

    /* 批取数缓冲（逐批读入、逐行返回） */
    HeapTuple      *tuples;
    int             num_tuples;
    int             next_tuple;
    bool            eof_reached;

    MemoryContext   batch_cxt;       /* 每批 reset 一次性回收 */
    MemoryContext   temp_cxt;
} IcebergScanState;
```

`fileScanTasks` / `retrievedAttrs` 由 `Begin` 从 `fdw_private` 解码填入；`rel`/`tupdesc`、`reader`、批缓冲字段（沿用 postgres_fdw / pg_lake 同名字段）、`*_cxt` 由 `Begin` 现场建立，缓冲字段在 `Iterate`/`fetch_more_data`/`ReScan` 间推进重置，`*_cxt` 在 `End` 释放。

### 2.3 `FileScanTask`

**内容**：单个数据文件的扫描描述（数据文件路径、文件格式）。投影与谓词是整次扫描共享的，不放进逐文件 task。

**产出**：Catalog 只缓存当前指针与 snapshot 摘要，**不缓存 manifest / data file 明细**（见 §4），故 `FileScanTask` 必须在运行期读对象存储产出：

```
snapshots.manifest_list（已缓存普通列）→ manifest → data file → FileScanTask
```

入口直接取 `snapshots.manifest_list`（缓存命中，免读 `metadata.json`，对应 Catalog 设计的 V2 快路径）；缺失时回退解析 `metadata.json`。manifest / data file 始终未缓存，**必读对象存储**——这一点确定，唯一待定是产出时机。

**待定（产出时机）**：放规划期还是执行期，直接决定 `IcebergPrivFileScanTasks` 承载完整任务列表还是仅承载入口指针。

| 方案 | `fdw_private` 承载 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 规划期（`GetForeignPlan` 内 `PlanFiles`） | 完整 `FileScanTask` 列表 | 规划期即知文件数，利于代价估计；类似 pg_lake DuckDB 路径物化文件列表 | 规划期做对象存储 IO；缓存/预备计划下 snapshot 可能在执行前漂移 |
| B. 执行期（推迟到 `BeginForeignScan`） | 仅 `manifest_list` / `snapshot_id` | 规划轻；snapshot 在执行期解析更一致；与 pg_lake SDK 路径先例一致 | 规划期无文件级信息，代价估计受限 |

考虑因素：规划期是否容忍对象存储 IO；缓存/预备计划下 snapshot 是否漂移；是否需要规划期文件级代价信息。因两者权衡未定，暂列待定。

> Iceberg V2 读时合并（MOR）的 delete file 引用随 delete 支持引入，届时 `FileScanTask` 需扩展携带关联 delete file 列表。

## 3. 回调详细设计

执行次序与数据流：规划期 `GetForeignRelSize → GetForeignPaths → GetForeignPlan`（产出 `fdw_private`）；执行期 `Begin → Iterate（重复）→ End`，`ReScan` 重置游标重扫；`Explain` 读 `fdw_private`，不依赖执行态。各回调输入由规划器/执行器传入，对元信息表与对象存储的访问在回调内经 SPI 或 reader 发起，统一列在「依赖」项下。

| 回调 | 触发时机 | 职责 |
| --- | --- | --- |
| `GetForeignRelSize` | 规划 | 估行，写 `baserel->rows` |
| `GetForeignPaths` | 规划 | 登记全表扫描路径 |
| `GetForeignPlan` | 规划 | 解析 Catalog + PlanFiles，编码 `fdw_private`，生成节点 |
| `BeginForeignScan` | 执行开始 | 解码 `fdw_private`，建扫描态与内存上下文 |
| `IterateForeignScan` | 逐行（热路径） | 批缓存状态机，逐行返回 tuple |
| `EndForeignScan` | 执行结束 | 释放 reader 与内存上下文 |
| `ReScanForeignScan` | 重扫 | 重置游标 |
| `ExplainForeignScan` | EXPLAIN | 附加扫描来源信息 |

### 3.1 `GetForeignRelSize`

估计外表返回行数，供优化器比较路径代价。

- **输入**：`PlannerInfo *root`（规划上下文）、`RelOptInfo *baserel`（外表关系优化信息）、`Oid foreigntableid`（外表 OID）。
- **输出**：无返回值；写 `baserel->rows`（估计返回行数）。平均行宽由优化器按列类型给出，未接入 ANALYZE 统计前 FDW 不另设。

```
void GetForeignRelSize(root, baserel, foreigntableid):
    // 1. 取表身份：table OPTIONS(namespace/table_name) + server OPTIONS(catalog 配置)
    ident = IcebergGetTableIdentity(foreigntableid)
    baserel->fdw_private = ident                    // 暂存供后续回调复用

    // 2. 取表基数（当前 snapshot 的总记录数）—— 来源待定，见「依赖」
    rows = IcebergGetTableCardinality(ident)

    // 3. 按谓词联合选择率折算，写回估计行数
    sel = clauselist_selectivity(root, baserel->baserestrictinfo, ...)
    baserel->rows = rows * sel
```

- **依赖（待定）**：表基数需要当前 snapshot 的 `total-records`。该值在 Iceberg snapshot summary 中，但 `iceberg_catalog.snapshots` 只缓存 `operation`，**不缓存 summary 统计**，故 Catalog 不提供记录数。两条路：
  - 方案1：增加 `total_records BIGINT` 列，commit 时从 summary 写入；估行直接 `SELECT total_records FROM snapshots WHERE table_uuid=? AND snapshot_id=<current>`。与 Catalog 缓存统计、规避规划期 IO 的做法一致。
  - 方案2：规划期读 `metadata.json` 当前 snapshot summary 取 `total-records`：不改元表，但每次规划增加一次对象存储访问。

### 3.2 `GetForeignPaths`

生成外表访问路径并登记到候选集。

- **输入**：`PlannerInfo *root`、`RelOptInfo *baserel`、`Oid foreigntableid`。
- **输出**：无返回值；向 `baserel->pathlist` 登记一条全表扫描 `ForeignPath`。
- **依赖**：无；不访问元信息表或对象存储（表身份已在 §3.1 暂存于 `baserel->fdw_private`）。

```
void GetForeignPaths(root, baserel, foreigntableid):
    path = create_foreignscan_path(root, baserel, ...)   // 单条全表扫描路径，无 pathkeys
    add_path(baserel, path)
```

### 3.3 `GetForeignPlan`

将选中路径固化为 `ForeignScan` 节点，解析 Catalog 与数据文件，编码 `fdw_private`。

- **输入**：`PlannerInfo *root`、`RelOptInfo *baserel`、`Oid foreigntableid`、`ForeignPath *best_path`（选中路径）、`List *tlist`（目标列）、`List *scan_clauses`（扫描谓词，一组 `RestrictInfo`）、`Plan *outer_plan`（openGauss 特有）。
- **输出**：`ForeignScan *` 计划节点（`make_foreignscan` 构造，`fdw_private` 为第 5 参）。

```
ForeignScan *GetForeignPlan(root, baserel, foreigntableid,
                            best_path, tlist, scan_clauses, outer_plan):
    // 1. 剥去 RestrictInfo 外壳，得裸谓词表达式，作为节点 qual（由执行器重过滤）
    scan_quals = extract_actual_clauses(scan_clauses, false)

    // 2. 解析 Catalog：SPI 查 tables，全为普通列，无对象存储访问
    ident = baserel->fdw_private                         // 复用 RelSize 阶段
    meta  = IcebergCatalogResolveTable(ident)
        // → SELECT metadata_location, current_schema_id, current_snapshot_id, table_uuid
        //     FROM <catalog_schema>.tables WHERE namespace=$1 AND table_name=$2
        // → 命中 0 行报 NoSuchTable

    // 3. 算投影列属性号（取自外表 tupdesc / targetlist，不需 Iceberg schema）
    retrievedAttrs = BuildRetrievedAttrs(baserel, tlist)

    // 4. 产出 FileScanTask 列表（读对象存储；产出时机见 §2.3 待定）
    fileScanTasks = PlanFiles(meta)

    // 5. 编码 fdw_private（按 §2.1 枚举顺序），构造并返回节点
    fdw_private = IcebergBuildScanPrivate(fileScanTasks, retrievedAttrs)
    return make_foreignscan(tlist, scan_quals, scanrelid, ..., fdw_private, ...)
```

- **依赖（上游元信息表）**：
  - 步骤 2 SPI 查 `iceberg_catalog.tables`，取 `metadata_location` / `current_schema_id` / `current_snapshot_id` / `table_uuid`，**均为普通列**，一次查询取得，**不访问对象存储**。其中 `current_schema_id` / `current_snapshot_id` 仅随计划下传给 reader（reader 据此读 schema、定位 snapshot），FDW 层不解释列结构。
  - 步骤 4 `PlanFiles` 若在规划期执行（方案 A），先按 `(table_uuid, current_snapshot_id)` SPI 查 `iceberg_catalog.snapshots` 取 `manifest_list`（普通列，缓存命中），再读对象存储展开 manifest → data file。
- **待定**：步骤 4 的 `FileScanTask` 产出时机（§2.3）。

### 3.4 `BeginForeignScan`

建立执行态，解码 `fdw_private`，初始化内存上下文与批游标。

- **输入**：`ForeignScanState *node`（扫描执行态节点）、`int eflags`（执行标志位）。
- **输出**：无返回值；设 `node->fdw_state` 指向新建 `IcebergScanState`（`EXEC_FLAG_EXPLAIN_ONLY` 时保持 `NULL`）。

```
void BeginForeignScan(ForeignScanState *node, int eflags):
    if eflags & EXEC_FLAG_EXPLAIN_ONLY:
        return                                       // fdw_state 保持 NULL，不分配资源

    festate = palloc0(sizeof(IcebergScanState))
    festate->rel     = node->ss.ss_currentRelation
    festate->tupdesc = RelationGetDescr(festate->rel)

    // 解码 fdw_private（顺序严格对应 §2.1 编码）
    festate->fileScanTasks  = list_nth(plan->fdw_private, IcebergPrivFileScanTasks)
    festate->retrievedAttrs = list_nth(plan->fdw_private, IcebergPrivRetrievedAttrs)

    festate->batch_cxt = AllocSetContextCreate(...)
    festate->temp_cxt  = AllocSetContextCreate(...)
    festate->tuples = NULL; festate->num_tuples = 0
    festate->next_tuple = 0; festate->eof_reached = false

    festate->reader = ReaderOpen(festate->fileScanTasks,
                                 festate->retrievedAttrs, ...)   // 下半层
    node->fdw_state = festate
```

- **依赖**：解码顺序与 §2.1 编码顺序严格对应；不访问 Catalog 或对象存储（对象存储访问在 reader 内）。
- **待定**：`ReaderOpen` 属下半层；方案 B 下文件规划在此处由 reader 内部完成（入参为 `manifest_list` / `snapshot_id`）。

### 3.5 `IterateForeignScan`

每次返回一行；数据耗尽返回空槽表示结束。PG 每次只取一行，reader 一次返回整批，故内部维护批缓存状态机。

- **输入**：`ForeignScanState *node`。
- **输出**：`TupleTableSlot *`；含一行数据的扫描槽，或经 `ExecClearTuple` 清空的空槽（结束）。
- **依赖**：无上游元信息表访问；取数经 reader（对象存储）发起。

```
TupleTableSlot *IterateForeignScan(ForeignScanState *node):
    festate = node->fdw_state
    if festate == NULL:                              // EXPLAIN-only
        return ExecClearTuple(slot)

    // 批已耗尽则拉下一批
    if festate->next_tuple >= festate->num_tuples:
        fetch_more_data(festate)
        if festate->num_tuples == 0:                 // reader 结束
            return ExecClearTuple(slot)

    return ExecStoreTuple(festate->tuples[festate->next_tuple++], slot)

fetch_more_data(festate):
    MemoryContextReset(festate->batch_cxt)           // 回收上一批
    festate->tuples = ReaderNextBatch(festate->reader, &festate->num_tuples)  // 下半层
    festate->next_tuple = 0
```

- **待定**：`ReaderNextBatch` 取数体属下半层（`IcebergReaderNextBatch → ArrowColumnToDatums`），替换不影响本过程与 FDW 接线。

### 3.6 `EndForeignScan` 与 `ReScanForeignScan`

二者输入均为 `ForeignScanState *node`，均无返回值，均不访问上游元信息表。`End` 结束扫描、释放 reader 与内存上下文；`ReScan` 重置游标使后续 `Iterate` 从头重扫，支持相关子查询等子计划重扫。

```
void EndForeignScan(ForeignScanState *node):
    festate = node->fdw_state
    if festate == NULL:                              // EXPLAIN-only
        return
    ReaderClose(festate->reader)                     // 下半层
    MemoryContextDelete(festate->batch_cxt)          // 即使未接真实 reader 也须释放，防泄漏
    MemoryContextDelete(festate->temp_cxt)
```

```
void ReScanForeignScan(ForeignScanState *node):     // 低优，最小实现
    festate = node->fdw_state
    if festate == NULL:
        return
    MemoryContextReset(festate->batch_cxt)
    festate->tuples = NULL; festate->num_tuples = 0  // 批缓冲归零
    festate->next_tuple = 0; festate->eof_reached = false
    ReaderRewind(festate->reader)                    // 从首个 task 重读
```

### 3.7 `ExplainForeignScan`

在 EXPLAIN 输出中附加扫描来源信息。

- **输入**：`ForeignScanState *node`、`ExplainState *es`（EXPLAIN 输出状态）。
- **输出**：无返回值；经 `ExplainPropertyText` 向 `es` 追加附加项。
- **依赖**：仅读 `plan->fdw_private`（规划期已解析的结果），不依赖 `fdw_state`、不访问元信息表，故 EXPLAIN-only（`fdw_state == NULL`）下安全。

```
void ExplainForeignScan(ForeignScanState *node, ExplainState *es):
    fdw_private = node->ss.ps.plan->fdw_private
    // 输出规划期解析到的来源标识：方案 A 下为文件数，方案 B 下为 manifest_list/snapshot_id
    ExplainPropertyText("Iceberg source", DescribeSource(fdw_private), es)
```

- **待定**：具体附加项（文件数 / `manifest_list` / `snapshot_id`）随 §2.3 的产出时机决策确定。

## 4. 上下游边界

FDW 层只需一个只读解析入口，将外表身份解析为权威指针与 snapshot 摘要；列结构解析与文件读取交给 reader。边界与 Catalog 元信息表设计（`GaussVector_Iceberg_Catalog_Design.md`）一致。

### 4.1 `IcebergCatalogResolveTable`（pg_native）

把外表身份 `(namespace, table_name)` 解析为权威 `metadata.json` 路径与当前 schema / snapshot 指针，对应 Iceberg `loadTable` 的只读部分，仅依赖 `iceberg_catalog.tables`。

- **入口**：`IcebergGetTableIdentity(foreigntableid)` 从 table OPTIONS 取 `namespace`/`table_name`，从 server OPTIONS 取 `catalog_kind`/`catalog_schema`。
- **解析**：SPI 查 `<catalog_schema>.tables`：
  `SELECT metadata_location, current_schema_id, current_snapshot_id, table_uuid FROM <schema>.tables WHERE namespace=$1 AND table_name=$2`。
  - schema 名经 `quote_identifier` 处理大小写与防注入；命中 0 行报 `ERRCODE_UNDEFINED_OBJECT`（NoSuchTable）；`metadata_location` 为空报错。
  - 结果须在 `SPI_finish` 前 `pstrdup` 到调用方上下文。
- **结果**：`{ metadataLocation, currentSchemaId, currentSnapshotId, tableUuid }`。
- **待定（备选解析路径）**：`tables` 设有 `UNIQUE (relid)` 列（本地 relation 绑定）。若外表创建时将其 OID 写入 `tables.relid`，可改用 `WHERE relid = foreigntableid` 直接解析，免依赖 OPTIONS 正确性。但纯外部表 `relid` 允许为空，需 Catalog 注册侧配合，故暂以 `(namespace, table_name)` 为主路径。

### 4.2 上游元数据表依赖

FDW 层规划期消费的元数据，及其在 Catalog 表中的形态与取用方式（直接回答「字段是否已在表结构中 / 是否 JSON 封装 / 是否需规划期访问对象存储」）：

| 数据 | Catalog 表中的形态 | 取用方式 | 规划期对象存储 IO | 使用方 |
| --- | --- | --- | --- | --- |
| `metadata_location` | `tables` 普通列 | SPI 查 `tables` | 否 | `GetForeignPlan`（PlanFiles 回退入口） |
| `current_snapshot_id` | `tables` 普通列 | SPI 查 `tables` | 否 | `GetForeignPlan` 定位待扫描 snapshot；`RelSize` 定位估行 snapshot |
| `current_schema_id` | `tables` 普通列 | SPI 查 `tables` | 否 | `GetForeignPlan` 下传 reader（FDW 不解释列结构） |
| `table_uuid` | `tables` 普通列 | SPI 查 `tables` | 否 | 关联 `snapshots` / `table_schemas` 行 |
| `manifest_list` | `snapshots` 普通列 | SPI 查 `snapshots`（按 `table_uuid` + `current_snapshot_id`） | 否 | `PlanFiles` 入口 |
| 表记录数 `total-records` | **未缓存**（`snapshots` 仅存 `operation`） | 待定：扩 `snapshots` 列 / 读 `metadata.json` | 待定（§3.1） | `GetForeignRelSize` |
| `schema_json` | `table_schemas` **JSONB（JSON 封装）** | reader 解析 JSON | —（reader 期） | reader 列对应（§4.3） |
| manifest / data / delete file 明细 | **未缓存**（设计明确排除持久化） | 读对象存储 | `PlanFiles` 必读（时机待定，§2.3） | `PlanFiles` / reader |

**边界**：Catalog 对 FDW 层只提供到「当前指针 + snapshot 摘要」为止；manifest 与数据文件明细不在 Catalog 内（GaussVector 不缓存 `manifest_files`/`data_files`/`delete_files`），须运行期读对象存储解析。FDW 层不读 `schema_json`、不读 manifest——前者归 reader，后者归 `PlanFiles`。

### 4.3 下游 reader 接口与边界

reader 是 FDW 层的取数后端（自有 parquet reader 或 Iceberg SDK），对 FDW 层是不透明句柄。接口参照 pg_lake SDK 桥接的 open / next / close 三步：

| 阶段 | 形态（示意） | FDW 层传入 | reader 返回 |
| --- | --- | --- | --- |
| 打开 | `reader = ReaderOpen(...)` | FileScanTask 列表（方案 A），或 `manifest_list` + `snapshot_id`（方案 B，reader 内部 PlanFiles）；外加 `retrievedAttrs`、`current_schema_id` | reader 句柄 |
| 取批 | `tuples = ReaderNextBatch(reader, &n)` | — | 一批 HeapTuple（`n = 0` 表示结束） |
| 关闭 | `ReaderClose(reader)` | — | — |

**边界**：FDW 层只负责把「读哪些文件、投影哪些列、按哪个 schema」交给 reader，并逐行返回 tuple。以下完全由 reader 承担：

- 读 `manifest`（方案 B 下）/ `*.parquet`；
- 读 `table_schemas.schema_json`（JSONB），按 `field_id` 对应文件列到表列（schema evolution）并做类型映射；
- 应用 delete file（V2 MOR）。
