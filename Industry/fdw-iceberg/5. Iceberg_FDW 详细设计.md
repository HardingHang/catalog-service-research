# GaussVector - Iceberg FDW 层详细设计

## 1. 设计背景

### 1.1 设计目标与范围

本设计实现 Iceberg 外表只读扫描的 FDW 层：执行器查询外表时，依次执行规划回调函数，解析 Catalog 得到表身份与数据文件描述，生成 `ForeignScan` 计划节点；执行期调用函数按描述扫描返回元组。

实现以 openGauss `src/include/foreign/fdwapi.h` 与 `contrib/file_fdw` 为接口与模板基准，以 GaussVector `iceberg_catalog.*` 元信息表作为元数据来源。

| 项目      | 范围                                                       |
| --------------- | ------------------------------------------------------------ |
| 形态 | 仅行式 tuple 路径 |
| 逻辑结构 | 二级命名 `namespace.table_name`，`namespace` 对应数据库 schema，不支持多级嵌套 namespace |
| Catalog 后端 | `pg_native` |
| 回调函数     | 7 个：`GetForeignRelSize`、`GetForeignPaths`、`GetForeignPlan`、`BeginForeignScan`、`IterateForeignScan`、`EndForeignScan`、`ExplainForeignScan` |

### 1.2 FDW 整体架构

FDW 层分规划期与执行期两条回调路径，二者通过 `ForeignScan` 节点上的 `fdw_private` 传递数据。规划期读 Catalog 元信息，执行期由 reader 读对象存储中的数据文件。

```
SQL / 执行器：SELECT ... FROM <iceberg 外表>
  │
  ├─ 规划期回调
  │    GetForeignRelSize    估行
  │    GetForeignPaths      生成访问路径
  │    GetForeignPlan       解析 Catalog + PlanFiles，编码 fdw_private，生成 ForeignScan
  │      │
  │      ├─→ Catalog 解析（只读）：IcebergCatalogResolveTable
  │      │     └─ SPI → iceberg_catalog.tables / snapshots
  │      │            （当前指针 + snapshot 摘要；不含 manifest/data 明细）
  │      │
  │      └─→ PlanFiles：metadata.json → manifest list → manifest → data file
  │             （读对象存储，产出 FileScanTask；产出时机见 §2.3）
  │
  │   fdw_private 随 ForeignScan 节点传给执行期
  │
  └─ 执行期回调
       BeginForeignScan     解码 fdw_private，建立扫描态与内存上下文
       IterateForeignScan   批缓存，逐行返回 tuple
       EndForeignScan       释放 reader 与内存上下文（ReScan：重置游标后重扫）
         │
         └─→ reader（句柄，下半层）：FileScanTask → *.parquet / delete → Arrow → tuple
```

### 1.3 FdwRoutine 注册

handler 用 `makeNode(FdwRoutine)` 创建结构（未赋值字段自动为 `NULL`），逐字段赋回调指针：

| 字段 | 赋值 | 说明 |
| --- | --- | --- |
| `GetForeignRelSize` / `GetForeignPaths` / `GetForeignPlan` | 是 | 规划三回调（§3.1–3.3） |
| `BeginForeignScan` / `IterateForeignScan` / `EndForeignScan` | 是 | 扫描生命周期（§3.4–3.6） |
| `ReScanForeignScan` | 是（最小实现） | 子计划重扫（§3.6） |
| `ExplainForeignScan` | 是 | EXPLAIN 附加输出（§3.7） |
| Modify 族、Join/Upper 下推、采样、内存统计等 | `NULL` | 不实现 |

handler 与 validator 以 `extern "C"` + `PG_FUNCTION_INFO_V1` 导出；extension 安装脚本声明二者并 `CREATE FOREIGN DATA WRAPPER`。

### 1.4 OPTIONS 配置与校验

OPTIONS 是在 FDW 对象（FOREIGN TABLE、SERVER）上用 `CREATE ... OPTIONS(...)` 声明的键值配置，随对象存于系统目录（`pg_foreign_table`、`pg_foreign_server`），记录外表对应哪张 Iceberg 表、使用哪个 catalog 后端。openGauss/PG 的 FDW 对象模型要求每张外表必须归属一个 SERVER（`CREATE FOREIGN TABLE ... SERVER s`），SERVER 再绑定 FOREIGN DATA WRAPPER。`catalog_kind`/`catalog_schema` 是该 server 下所有外表共享的后端配置，按此模型置于 server 而非逐表重复。

| 层级 | OPTION | 必需 | 用途 |
| --- | --- | --- | --- |
| server | `catalog_kind` | 否（默认 `pg_native`） | Catalog 后端，默认 `pg_native` |
| server | `catalog_schema` | 否（默认 `iceberg_catalog`） | `pg_native` 元信息表所在 schema |
| table | `namespace` | 是 | Iceberg 表所属 namespace（对应 DB schema） |
| table | `table_name` | 是 | Iceberg 表名 |

校验规则：

1. 逐项检查 key 是否属于当前对象类型（server / 外表）的允许集合，非法 key 报 `ERRCODE_FDW_INVALID_OPTION_NAME`，并在提示中列出该类型的合法 key。
2. 外表缺 `namespace` 或 `table_name` 报 `ERRCODE_FDW_DYNAMIC_PARAMETER_VALUE_NEEDED`。校验在 DDL（`CREATE`/`ALTER FOREIGN TABLE`）时执行，使错误尽早暴露而非延迟到查询时。

## 2. 数据结构

同一份扫描所需信息，在 DDL、规划、执行三个阶段分别由不同数据结构承载，后一阶段的数据由前一阶段生成：

| 阶段 | 数据 | 存储位置 | 由谁生成 | 由谁使用 |
| --- | --- | --- | --- | --- |
| DDL | OPTIONS | 系统目录（`pg_foreign_table` / `pg_foreign_server`） | `CREATE ... OPTIONS`，validator 校验 | 规划回调 |
| 规划 | `fdw_private` | `ForeignScan` 计划节点（可 `copyObject` 序列化） | `GetForeignPlan`：读 OPTIONS 并解析 Catalog 后生成 | 执行回调 |
| 执行 | `IcebergScanState` | 进程内存（`node->fdw_state`） | `BeginForeignScan`：解码 `fdw_private` 后生成 | `Iterate` / `End` |

规划回调与执行回调不共享内存，只能通过 `fdw_private` 传递；OPTIONS 不复制进 `fdw_private`，执行期使用 `fdw_private` 中的解析结果，一般不再读 OPTIONS。本章定义 `fdw_private` 与执行态结构（OPTIONS 见 §1.4）。

### 2.1 `fdw_private` 编码

按固定枚举顺序装配一个 `List`，各项均为可序列化节点（子 `List` / `IntList` / `String` / `NIL`）：

```c
enum IcebergScanPrivateIndex {
    IcebergPrivFileScanTasks,   /* 数据文件扫描描述（FileScanTask）列表 */
    IcebergPrivRetrievedAttrs,  /* 投影列属性号 List<int> */
};
```

- **`IcebergPrivFileScanTasks`**：本次扫描要读的数据文件描述列表（内容与产出时机见 §2.3）。
- **`IcebergPrivRetrievedAttrs`**：需要读取并回填的外表列属性号（attno）列表，决定 reader 的列裁剪与 tuple 填充范围。

暂不使用谓词项 `IcebergPrivResidualQuals`：不向 reader 下推谓词，局部谓词的重过滤由执行器对 `ForeignScan` 节点的 qual 列（即 `make_foreignscan` 传入的 `scan_clauses`）自动完成，无需在 `fdw_private` 另存。将来接入 reader 端文件/行裁剪时，再增加裁剪谓词项及其执行态字段。

不使用 field_id：按 `field_id` 把文件列对应到当前表列是 reader 的工作（下半层，见 §4.3），FDW 层仅用属性号（`IcebergPrivRetrievedAttrs`）表达投影。

### 2.2 `IcebergScanState` 执行态

```c
typedef struct IcebergScanState {
    Relation        rel;
    TupleDesc       tupdesc;
    List           *fileScanTasks;   /* 解码自 fdw_private */
    List           *retrievedAttrs;

    void           *reader;          /* 取数 reader 句柄；FDW 层不关心其内部实现 */

    /* 批取数缓冲（fetch buffer，逐批读入、逐行返回） */
    HeapTuple      *tuples;
    int             num_tuples;
    int             next_tuple;
    bool            eof_reached;

    MemoryContext   batch_cxt;       /* 每批 reset 一次性回收 */
    MemoryContext   temp_cxt;
} IcebergScanState;
```

`fdw_private` 的两个数据项各对应 `IcebergScanState` 的一个字段，由 `BeginForeignScan` 解码后填入：

| `fdw_private` 项 | 编码者 | 解码 → 执行态字段 | 维护责任 |
| --- | --- | --- | --- |
| `IcebergPrivFileScanTasks` | `GetForeignPlan` | `IcebergScanState.fileScanTasks` | `Begin` 解码；reader 据此打开/推进 |
| `IcebergPrivRetrievedAttrs` | `GetForeignPlan` | `IcebergScanState.retrievedAttrs` | `Begin` 解码；reader 据此裁剪列 |

局部谓词没有对应的执行态字段：它们在 `make_foreignscan` 时作为 `ForeignScan` 节点的 qual 列传入，由执行器在每行返回后自动重过滤，不经 `fdw_private`、也不进 `IcebergScanState`。

执行态中不来自 `fdw_private` 的字段，由 `BeginForeignScan` 现场建立并维护：`rel`/`tupdesc`（取自扫描关系）、`reader`、批取数缓冲字段 `tuples`/`num_tuples`/`next_tuple`/`eof_reached`（沿用 postgres_fdw、pg_lake 取数缓冲的同名字段）、`batch_cxt`/`temp_cxt`。其中取数缓冲字段在 `Iterate`/`fetch_more_data`/`ReScan` 间推进与重置，`*_cxt` 在 `End` 释放。

### 2.3 `FileScanTask`

**内容**：单个数据文件的扫描描述，至少包括：数据文件路径、文件格式。投影与谓词是整次扫描共享的，分别由 `IcebergPrivRetrievedAttrs` 与节点 qual 承载，不放进逐文件的 task。

**来源**：假设 GaussVector Catalog 只提供该解析的入口与摘要，持久化当前指针与高频缓存（schema / spec / snapshot 摘要），不复制 manifest file / data file 明细，则 `FileScanTask` 无法由元信息表直接提供，必须在运行期沿 `metadata_location → snapshot → manifest list → manifest → data file` 解析对象存储产出（即 `PlanFiles` 等价过程）。

**方案对比**：

- pg_lake DuckDB 路径：由 pg_lake_iceberg 预先把 snapshot→manifest→data file 解析为显式文件列表并缓存（data files 目录表），规划期直接把文件路径喂给 DuckDB（`read_parquet('s3://.../data_0.parquet')`）。文件清单被物化，且来自缓存而非每次读 manifest。
- pg_lake SDK 路径：把 `metadata_location` 传给 Iceberg SDK，文件规划在 SDK 内部、于 `BeginForeignScan` 打开表时完成；FDW 层只持有一个不透明的 scan 句柄（`arrowScan`），`fdw_private` 不含任何文件列表（相当于下文方案 B，但委托给 SDK）。
- 第三路径：GaussVector 既不缓存文件清单也不使用 SDK，故 `PlanFiles` 是自有代码且需实时读 manifest，`FileScanTask` 是 FDW 层显式、可序列化的对象；其产出时机需自行决策（见「待定」）。

**依赖**：

- `iceberg_catalog.tables`：`metadata_location`（解析入口）、`current_snapshot_id`（待扫描 snapshot）。
- 对象存储：`metadata.json` 及其引用的 manifest list / manifest / data file。

**待定**：`PlanFiles` 需访问对象存储，放在规划期还是执行期，直接决定 `IcebergPrivFileScanTasks` 承载完整任务列表还是仅承载入口指针。

- 原因：GaussVector 不缓存文件清单，`PlanFiles` 必然要读对象存储；两种时机各有代价，且影响代价估计。

- 考虑因素：规划期是否容忍对象存储 IO；prepared / 缓存计划下 snapshot 是否会在执行前漂移；是否需要规划期的文件级代价信息。

- 可选方案：

  | 方案 | `fdw_private` 承载 | 优点 | 代价 |
  | --- | --- | --- | --- |
  | A. 规划期产出（`GetForeignPlan` 内 `PlanFiles`） | 完整 `FileScanTask` 列表 | 规划期即知文件数，利于代价估计 | 规划期做对象存储 IO；缓存/预备计划下 snapshot 可能在执行前漂移 |
  | B. 执行期产出（推迟到 `BeginForeignScan`） | 仅 `metadata_location` / `snapshot_id` | 规划轻；snapshot 在执行期解析更一致 | 规划期无文件级信息，代价估计受限 |

  - 方案 A 利于规划期代价（类似 DuckDB 路径物化文件列表），但需解决缓存计划下的 snapshot 漂移、且规划期需访问对象存储；
  - 方案 B 更轻，且与 SDK 路径先例一致。因 GaussVector 不缓存文件清单、两者权衡未定，暂列待定。


此外，Iceberg V2 读时合并（MOR）的 delete file 引用随 delete 支持引入，届时 `FileScanTask` 需扩展携带关联 delete file 列表。

## 3. 回调详细设计

执行次序与数据流如下，函数签名以 openGauss `fdwapi.h` 为准。

- 规划期回调依次执行并产出 `fdw_private`；
- 执行期 `Begin → Iterate（重复）→ End`；
- `Explain` 读 `fdw_private`，不依赖执行态。

```
规划期：
  GetForeignRelSize → GetForeignPaths → GetForeignPlan
      GetForeignPlan 内：解析 Catalog → PlanFiles → 编码 fdw_private → 生成 ForeignScan 节点

  fdw_private 随 ForeignScan 节点传给执行期

执行期：
  BeginForeignScan → IterateForeignScan（重复 N 次）→ EndForeignScan
      Begin：解码 fdw_private、建立扫描态
      Iterate：批缓存，逐行返回 tuple
      End：释放 reader 与内存
  ReScanForeignScan：重置游标后重新扫描

EXPLAIN：
  ExplainForeignScan：读 ForeignScan.fdw_private（不依赖执行态）
```

各回调的**输入参数均由规划器/执行器在调用时传入**（如 `root`、`baserel`、`foreigntableid`、`node`、`eflags`）；对上层元信息表与对象存储的访问不在输入参数中，而是回调内部经 Catalog（SPI）或 reader 发起，统一列在「依赖」项下。

### 3.1 `GetForeignRelSize`

- **功能**：估计外表扫描返回的行数，供优化器比较路径代价。

- **输入**：`PlannerInfo* root`（规划上下文）、`RelOptInfo* baserel`（外表关系优化信息）、`Oid foreigntableid`（外表 OID）。

- **输出**：无返回值（`void`）；写 `baserel->rows`（估计返回行数）。平均行宽由优化器按列类型给出，未接入 ANALYZE 统计前 FDW 不另设。

- **过程**：
  1. 经 `GetForeignTable(foreigntableid)->options` 取 table OPTIONS 的 `namespace`/`table_name`，经 `GetForeignServer(serverid)->options` 取 server OPTIONS 的 `catalog_kind`/`catalog_schema`（即 `IcebergGetTableIdentity`，§4.1），暂存于 `baserel->fdw_private` 供后续回调复用。
  2. 取当前 snapshot 的总记录数作为表基数（见「依赖」）。
  3. 以 `clauselist_selectivity(root, baserel->baserestrictinfo, ...)`（openGauss 优化器内置，估计谓词联合选择率）折算基数，写入 `baserel->rows`。

- **依赖**：表基数取自当前 snapshot 的 `total-records`。Iceberg 将其记录在 snapshot summary 中，但 GaussVector 现有 `iceberg_catalog.snapshots` 只缓存 `operation`、`manifest_list` 等，暂未缓存完整 summary，故不含记录数。需选择：

  - 扩展 `snapshots` 缓存，增加记录数列，由 commit 时从 snapshot summary 写入。结构示意：
    ```sql
    ALTER TABLE iceberg_catalog.snapshots
        ADD COLUMN total_records BIGINT;   -- 取自 snapshot summary.total-records
    -- 估行：
    -- SELECT total_records FROM iceberg_catalog.snapshots
    --     WHERE table_uuid = ? AND snapshot_id = <tables.current_snapshot_id>
    ```
  - 规划期读对象存储 `metadata.json` 的当前 snapshot summary 取 `total-records`（不改元表，但每次规划增加一次对象存储访问）。

  考虑因素：是否接受规划期访问对象存储；commit 路径是否接受维护统计列；估行精度要求。

  倾向：扩展 `snapshots` 缓存，与 pg_lake 缓存统计、规避规划期 IO 的做法一致。

### 3.2 `GetForeignPaths`

- **功能**：生成外表的访问路径并登记到候选路径集。
- **输入**：`PlannerInfo* root`、`RelOptInfo* baserel`、`Oid foreigntableid`。
- **输出**：无返回值（`void`）；向 `baserel->pathlist` 登记一条全表扫描 `ForeignPath`。
- **过程**：
  1. 调 `create_foreignscan_path` 构造一条全表扫描 `ForeignPath`（无 pathkeys、无 `required_outer`、无 `fdw_outerpath`）。
  2. 调 `add_path` 将该路径加入 `baserel->pathlist`。

### 3.3 `GetForeignPlan`

- **功能**：将选中路径固化为 `ForeignScan` 计划节点，解析 Catalog 与数据文件，编码 `fdw_private`。
- **输入**：`PlannerInfo* root`、`RelOptInfo* baserel`、`Oid foreigntableid`、`ForeignPath* best_path`（选中路径）、`List* tlist`（目标列）、`List* scan_clauses`（扫描谓词）、`Plan* outer_plan`（openGauss 特有）。
- **输出**：`ForeignScan*` 计划节点（由 `make_foreignscan` 构造，`fdw_private` 为第 5 参）。
- **过程**：
  1. `extract_actual_clauses(scan_clauses, false)`：`scan_clauses` 是优化器传入的一组 `RestrictInfo` 节点（每个 qual 被包成携带选择率等元信息的 `RestrictInfo`）；此函数取出每个 `RestrictInfo` 内层的布尔表达式（`.clause`），返回可直接作为计划节点 qual 的裸表达式列表（并按需丢弃 pseudoconstant）。做法同 file_fdw。
  2. `IcebergGetTableIdentity()`：从 OPTIONS 取 `namespace`/`table_name` 与 catalog 配置（§4.1）。
  3. `IcebergCatalogResolveTable()`：SPI 查 `tables` 取 `metadata_location` / `current_schema_id` / `current_snapshot_id` / `table_uuid`；命中 0 行报 NoSuchTable。
  4. 由查询目标列与 `baserel` 属性算出投影列属性号 `retrievedAttrs`（取自外表 `tupdesc`/targetlist，不需 Iceberg schema）。
  5. `PlanFiles()`：产出 `FileScanTask` 列表（来源与时机见 §2.3）。
  6. `IcebergBuildScanPrivate()`：按枚举顺序编码 `fdw_private`。
  7. `make_foreignscan()`：构造并返回 `ForeignScan` 节点。
- **依赖**：步骤 3 依赖 `iceberg_catalog.tables`（`metadata_location` / `current_schema_id` / `current_snapshot_id` / `table_uuid`）。其中 `current_schema_id` / `current_snapshot_id` 仅随计划下传给 reader（reader 据此读 schema、定位 snapshot，见 §4.3），FDW 层本身不解释列结构。
- **待定**：步骤 5 的 `FileScanTask` 来源与产出时机（§2.3）。

### 3.4 `BeginForeignScan`

- **功能**：建立执行态，解码 `fdw_private`，初始化内存上下文与批游标。
- **输入**：`ForeignScanState* node`（扫描执行态节点）、`int eflags`（执行标志位）。
- **输出**：无返回值（`void`）；设置 `node->fdw_state` 指向新建的 `IcebergScanState`（`EXEC_FLAG_EXPLAIN_ONLY` 时保持 `NULL`）。
- **过程**：
  1. `eflags & EXEC_FLAG_EXPLAIN_ONLY` 为真：直接返回，`fdw_state` 保持 `NULL`，不分配资源。
  2. `palloc0(IcebergScanState)`，填 `rel`、`tupdesc`。
  3. 从 `node->ss.ps.plan` 的 `fdw_private` 按枚举 `list_nth` 解码 `fileScanTasks`、`retrievedAttrs`。
  4. 创建 `batch_cxt`、`temp_cxt`。
  5. 初始化批游标：`tuples=NULL`、`num_tuples=0`、`next_tuple=0`、`eof_reached=false`。
  6. （下半层）按 `fileScanTasks`、`retrievedAttrs` 打开 reader。
  7. `node->fdw_state = festate`。
- **依赖**：步骤 3 的解码顺序与 §2.1 编码顺序严格对应。
- **待定**：步骤 6 打开 reader 属下半层。

### 3.5 `IterateForeignScan`

- **功能**：每次调用返回一行元组，数据耗尽时返回空槽表示结束。
- **输入**：`ForeignScanState* node`。
- **输出**：`TupleTableSlot*`；含一行数据的扫描槽，或经 `ExecClearTuple` 清空的空槽（结束）。
- **过程**（批缓存 + 逐行返回）：
  
  1. `fdw_state == NULL`（EXPLAIN-only）：`ExecClearTuple`，返回空槽。
  2. 批内仍有行（`next_tuple < num_tuples`）：跳至步骤 4。
  3. 批已耗尽：调 `fetch_more_data()` 读入下一批；若读得 0 行（reader 结束）：`ExecClearTuple`，返回空槽。
  4. `ExecStoreTuple(tuples[next_tuple++], slot)`，返回该 slot。
  
  `fetch_more_data`：在 `batch_cxt` 内 `MemoryContextReset` 回收上一批后读入下一批；批耗尽且 reader 结束时置 `num_tuples = 0`。
- **待定**：`fetch_more_data` 的取数体属下半层（`IcebergReaderNextBatch → ArrowColumnToDatums`），替换不影响本过程与 FDW 层接线。

### 3.6 `EndForeignScan` 与 `ReScanForeignScan`

**`EndForeignScan`**

- **功能**：结束扫描，释放 reader 与内存上下文。
- **输入**：`ForeignScanState* node`。
- **输出**：无返回值（`void`）。
- **过程**：
  1. `fdw_state == NULL`（EXPLAIN-only）：直接返回。
  2. （下半层）关闭 reader。
  3. `MemoryContextDelete(batch_cxt)`、`MemoryContextDelete(temp_cxt)`。即使尚未接入真实 reader，也需释放上下文，避免内存泄漏。

**`ReScanForeignScan`**（低优，最小实现）

- **功能**：重置扫描游标，使后续 `Iterate` 从头重扫，支持相关子查询等子计划重扫。
- **输入**：`ForeignScanState* node`。
- **输出**：无返回值（`void`）。
- **过程**：
  1. `fdw_state == NULL`：直接返回。
  2. `MemoryContextReset(batch_cxt)`。
  3. 取数缓冲字段归零（`tuples=NULL`、`num_tuples=0`、`next_tuple=0`、`eof_reached=false`），使下一次 `Iterate` 从第一个 task 重新读起。

### 3.7 `ExplainForeignScan`

- **功能**：在 EXPLAIN 输出中附加扫描来源信息。
- **输入**：`ForeignScanState* node`、`ExplainState* es`（EXPLAIN 输出状态）。
- **输出**：无返回值（`void`）；经 `ExplainPropertyText` 向 `es` 追加附加项。
- **过程**：
  1. 从 `node->ss.ps.plan` 取 `ForeignScan->fdw_private`。
  2. 按 `IcebergPrivFileScanTasks` 解码，取规划期解析到的 `metadata_location`。
  3. 经 `ExplainPropertyText` 输出该 `metadata_location`。
- **依赖**：读 `plan->fdw_private`，不依赖 `fdw_state`，故 EXPLAIN-only（`fdw_state == NULL`）下安全。
- **待定**：接入后可附加文件数 / `snapshot_id` 等来源信息。

## 4. 上下游边界

FDW 层只需一个只读解析入口，将外表身份解析为权威 `metadata_location` 与 schema 摘要。

### 4.1 `IcebergCatalogResolveTable`（pg_native）

`IcebergCatalogResolveTable` 把外表的表身份 `(namespace, table_name)` 解析为权威 `metadata.json` 路径与当前 schema / snapshot 指针，是规划回调定位待读数据的入口。它对应 Iceberg `loadTable` 的只读部分，仅依赖 `iceberg_catalog.tables`。

- **入口**：`IcebergGetTableIdentity(foreigntableid)` 从 table OPTIONS 取 `namespace`/`table_name`，从 server OPTIONS 取 `catalog_kind`/`catalog_schema`，是 §1.4 各 OPTION 的消费点。
- **解析**：经 SPI 查 `<catalog_schema>.tables`：
  `SELECT metadata_location, current_schema_id, current_snapshot_id, table_uuid FROM <schema>.tables WHERE namespace = $1 AND table_name = $2`。
  - schema 名来自 server OPTION，用 `quote_identifier` 处理大小写与防注入。
  - 命中 0 行报 `ERRCODE_UNDEFINED_OBJECT`（NoSuchTable）；`metadata_location` 为空报错。
  - 结果须在 `SPI_finish` 前切回调用方内存上下文 `pstrdup`，确保存活。
- **结果**：`{ metadataLocation, currentSchemaId, currentSnapshotId, tableUuid }`。

### 4.2 上游元信息表依赖与边界

FDW 层在规划期直接读取的元信息表与字段如下，全部经 `pg_native` 的 SPI 查询（§4.1）：

| 元信息表 | 消费字段 | 消费方 / 用途 |
| --- | --- | --- |
| `iceberg_catalog.tables` | `metadata_location` | `GetForeignPlan`：`PlanFiles` 起点 |
| | `current_snapshot_id` | `GetForeignPlan` 定位待扫描 snapshot；`GetForeignRelSize` 定位估行 snapshot |
| | `current_schema_id` | `GetForeignPlan`：随计划下传给 reader（FDW 层不解释列结构） |
| | `table_uuid` | 关联 `table_schemas` / `snapshots` 行 |
| `iceberg_catalog.snapshots` | 记录数列（需扩展，见 §3.1） | `GetForeignRelSize` 估行 |

**上界**：Catalog 对 FDW 层只提供到「当前指针 + snapshot 摘要」为止；manifest 与数据文件明细不在 Catalog 内（GaussVector 不缓存），须运行期读对象存储解析。FDW 层不读 `schema_json`、不读 manifest——前者归 reader（§4.3），后者归 `PlanFiles`。

### 4.3 下游 reader 接口与边界

reader 是 FDW 层的取数后端（自有 parquet reader 或 Iceberg SDK），对 FDW 层是不透明句柄。接口形态参照 pg_lake SDK 桥接的 open / next / close 三步：

| 阶段 | 形态（示意） | FDW 层传入 | reader 返回 |
| --- | --- | --- | --- |
| 打开 | `reader = ReaderOpen(...)` | FileScanTask 列表（方案 A），或 `metadata_location` + `snapshot_id`（方案 B，由 reader 内部 PlanFiles）；外加 `retrievedAttrs`、`current_schema_id` | reader 句柄 |
| 取批 | `tuples = ReaderNextBatch(reader, &n)` | — | 一批 HeapTuple（`n = 0` 表示结束） |
| 关闭 | `ReaderClose(reader)` | — | — |

**下界**：FDW 层只负责把「读哪些文件、投影哪些列、按哪个 schema」交给 reader，并逐行返回 reader 返回的 tuple。以下完全由 reader 承担、不在本设计展开：

- 读 `metadata.json` / manifest（方案 B 下）、读 `*.parquet`；
- 读 `iceberg_catalog.table_schemas.schema_json`，按 `field_id` 把文件列对应到当前表列（schema evolution）并做类型映射；
- 应用 delete file（V2 MOR）。

这条边界也解释了为何 `field_id`、`schema_json`、类型映射不出现在 §2–§3 的 FDW 层结构里：它们都在 reader 一侧。

### 4.4 外部依赖小结

本模块依赖的外部对象（元信息表、Iceberg 规范字段、对象存储）汇总：

| 依赖 | 来源 | 使用方 |
| --- | --- | --- |
| `iceberg_catalog.tables`（`metadata_location`/`current_schema_id`/`current_snapshot_id`/`table_uuid`） | GaussVector 元信息表 | FDW 层规划回调（§4.2） |
| `iceberg_catalog.snapshots`（记录数列，需扩展） | GaussVector 元信息表 | `GetForeignRelSize` 估行（§3.1） |
| `iceberg_catalog.table_schemas.schema_json` | GaussVector 元信息表 | reader 列对应（§4.3） |
| `field_id` | Iceberg 规范 | reader 列对应（§4.3） |
| `total-records` | Iceberg 规范（snapshot summary 键） | 表基数来源（§3.1） |
| `metadata.json` / manifest list / manifest / data file / delete file | 对象存储 | `PlanFiles` 与 reader 读取的对象 |
