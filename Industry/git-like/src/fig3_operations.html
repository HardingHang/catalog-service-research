图 3 · Nessie 实现的 Git-like 操作清单

点击任意操作卡片查看实现原理

必要（最小集）
有用（可后置）
不适用 / 不做
commit
必要
Git: 原子保存一组变更
写 CommitObj → refs 表 CAS 翻指针。单次 commit 可含多张表。
branch
必要
Git: 建独立工作线
refs 表新增一行，指向同一 CommitObj。零成本，不复制任何对象。
merge
必要
Git: 合并两条历史
replay 模式：逐 commit 重放，每次执行 OCC 校验。无行级自动合并。
log / history
必要
Git: 查看变更历史
沿 CommitObj.parent 字段单链遍历，时间复杂度 O(depth)。
diff
必要
Git: 对比两版本差异
比较两个 ref 的 StoreIndex，结果为 ContentKey（表名）级别变化，非行级。
revert / reset
必要
Git: 回退到历史版本
硬重置：refs.cas(branch, new=旧 commit_id)；或提交一次逆操作 commit。
tag
有用
Git: 不可变版本标签
refs 表新增一行，但禁止后续 CAS 修改。一次写入，永久固定。
cherry-pick / transplant
有用
Git: 移植单个 commit
从任意 ref 挑选指定 commit 序列，replay 到目标 branch。低频操作。
rebase / 行级 merge
不做
Git: 重写历史 / 合并文本
数据不应被重写；行级 merge 属于引擎职责，不在 Catalog 层实现。
