ETL（Extract-Transform-Load）

数据处理流水线程序，由数据工程师编写，在 Spark / Flink 上运行。从源系统抽取数据，经清洗转换后写入目标表。在 Nessie 场景中，ETL 程序就是向某个 branch 提交数据的写端。

DBA（数据库管理员）

负责监控数据平台健康状态、处理事故（如误删表后回滚）以及管理权限。在 Lakehouse 语境下，DBA 通过 SQL 工具操控 Spark / Trino，通过 Nessie CLI 查看 commit log 并执行 revert。

Catalog 的核心职责

唯一核心职责：维护"表名 → 当前有效 metadata.json 路径"的映射，并保证每次更新是原子的（CAS）。引擎不需要了解文件如何存储，只需向 Catalog 查询"该表当前在哪"。

Iceberg 与 Catalog 的分工

Iceberg 定义"文件如何组织成表"（格式规范）。Catalog 定义"哪个版本的文件当前有效"（指针服务）。写操作流程：Iceberg 生成新 metadata.json → Catalog 执行 CAS 翻指针 → 引擎下次查询时读到新版本。
